# Audio Splitter 代码审查报告

- **审查日期**：2026-11-16
- **审查对象**：`main @ b7e134f`（v2.0.0-multi 发布版）
- **审查方式**：纯静态阅读，未修改任何代码
- **代码规模**：C# 源文件约 20 个、1 万+ 行（MainForm.cs 3400+、OutputCard.cs 1000+），.NET Framework 4.8 + WinForms + NAudio 2.2.1

## 总体评价

这是一个**工程质量明显高于业余水准**的桌面音频工具：音频热路径零分配（`tmp/tmpF/ring` 全部预分配 `readonly` 字段）、配置原子写盘（`.tmp + File.Replace`，崩溃不留半截 ini）、时钟漂移闭环（`ClockGroup`）设计成熟、路由矩阵原子热替换、16 项自检、Release 0 错 0 警、0 个 TODO、MIT LICENSE、文档详实。以下问题多数是**可观测性与工程流程**层面的债务，而非功能缺陷——内核与音频路径的质量是这套代码里最好的部分。

## 问题清单（按严重程度排序）

### P0-1　95 处空 `catch { }`——故障排查黑洞

| | |
|---|---|
| 位置 | 全仓 142 处 catch 中 **95 处为空**；典型如 `src/Devices/DefaultChangeWatcher.cs:30`（系统默认设备变更回调静默吞异常）、`src/Infrastructure/SettingsStore.cs:47` |
| 影响 | 任何一处被吞掉的异常都意味着"功能悄悄失效"。设备热插拔、默认输出变更、端点音量回读这些**治理路径**恰恰最容易出问题，也恰恰全是空 catch——真出故障时日志里什么都没有 |
| 建议 | ① 音频回调路径（不能碰 I/O）改为 `Interlocked.Increment` 错误计数器，水位监控顺带上报；② 其余全部替换为 `SessionLog.WriteLine("[异常] …")` 一行；③ 编译期可开 [BannedApiAnalyzers] 或简单 grep 守门。工作量约半天，收益最大 |

| | |

### P1-4　ini 写到 exe 同目录——受限目录下静默失效　**【复核：误报，已实现并有实测保护】**

| | |
|---|---|
| 位置 | `src/Infrastructure/SettingsStore.cs`（以 exe 路径为基准） |
| 复核结论 | `MainForm.FlushSettings()` **已有完整失败分支**：写失败记 `[警告] 设置写入失败: <原因>；本次运行的改动可能不会保留 (<路径>)`，且 60 秒限流防刷屏（审查初稿漏读）。已实测：ini 设只读 → 改动设置 → 日志出现 `UnauthorizedAccessException` 警告，UI 同步可见 |
| 遗留建议（可选，低优先） | 长期可在持续失败时回退 `%APPDATA%\AudioSplitter\`，避免受限目录用户全程无持久化 |

### P1-5　EndpointAdmin 模糊匹配直接改系统状态

| | |
|---|---|
| 位置 | `src/Infrastructure/EndpointAdmin.cs`：`--setvol "名字片段:百分比"` / `--setdefault "名字片段"` 按名字子串匹配，命中即生效 |
| 影响 | 片段撞名（如 "CABLE" 同时匹配 CABLE-A/CABLE-B 前缀）会改错设备音量/默认输出；作为文档推荐的善后手段，误伤面比 UI 操作大 |
| 建议 | ① 多于一个匹配时**拒绝执行并列出候选**（若已有则确认；未验证）；② 加 `--list` 干跑模式；③ `--setvol` 之外建议都先 `--volprobe` 看一眼 |

### P1-6　音频实时线程与 UI 线程共享 monitor 锁

| | |
|---|---|
| 位置 | `src/Audio/DelayLine.cs:47/104`：`Read/Write` 每次持 `lock(sync)`，UI 改延迟（`SetDelay`）与 WASAPI 回调竞争同一监视器锁 |
| 影响 | .NET monitor 是竞争性锁：UI 线程持锁期间被 OS 抢占，音频线程最坏等一个时间片（~15ms）。标准档 160ms 余量完全无感；**极限档 60ms 总预估**时缓冲余量本就 ~15-20ms，被顶一下就是杂音。当前靠大缓冲掩盖，属已知实时性债务而非 bug |
| 建议 | 低成本：`SetDelay` 临界区内只做 `Interlocked.Exchange` 一个游标，搬移数据的活留给音频线程自己；彻底：双 ring 原子切换（与 `SetRouting` 原子换矩阵同一思路）。优先级不高，但若将来要把极限档余量再压低，这是第一块天花板 |

### P2-7　像素硬编码布局仅在本机 125% DPI 验证过

| | |
|---|---|
| 位置 | `MainForm.cs` 大量 `Location = new Point(x, y)` 固定坐标 + Anchor；卡片内部 `OutputCard.LayoutControls()` 相对摆放 |

### P2-8　SessionLog `AutoFlush = true` 每行刷盘

| | |
|---|---|
| 位置 | `src/Infrastructure/SessionLog.cs:33` |
| 影响 | UI 线程每条日志一次同步磁盘 I/O。稳态（30s 一条水位）无碍；启动/排障/断音风暴时段日志密集，理论上拖慢 UI 与音频治理线程 |
| 建议 | `AutoFlush = false` + `System.Threading.Timer` 每 2s `Flush()` 一次 + `FormClosing` 强制 Flush。风险极低，收益小，可与 P1-4 顺手一起做 |

### P3-11　其他小项（顺带记录）

- `crash_*.log` / session 日志含设备名与本地路径——纯本地文件、无上传，隐私风险可忽略；
- ini 为自研格式（非注入面），`SettingsStore` 解析有防呆——安全面整体**无网络、无外部输入解析、无敏感凭据**，风险极低；

- 版本线 `v0.9-baseline → v1.0.0-stereo → v2.0.0-multi` 清晰规范——保持。

## 值得保持的优点

1. **音频热路径零 GC 分配**——`DriftCorrectingProvider/DelayLine` 的缓冲全部构造期预分配，专业水准；
2. **原子性贯穿始终**——配置 `.tmp+Replace`、路由矩阵原子热替换、`File.Replace` 防半截文件；
3. **自检文化**——16 项 selftest 随每次构建跑，本次发布两个版本都带验证；
4. **实机验证习惯**——每轮改动都有 PowerShell/UIA 驱动的实测记录，而非"编译过就算";
5. **文档跟手**——README 重写 + docs 详实 + 版本线清晰。
