# 多路内核移植（routing-v2 ← main）

> 分支：`merge-kernel`（从 `routing-v2` 切出）
> 目标：把 `main` 上那套**多路 / 多声道内核**搬进当前工作区，保留 `routing-v2` 的输出卡片界面，
> 让"界面加几路，内核就发几路"真正成立。

---

## 一、为什么之前是"半成品"

`routing-v2` 的界面已经按"每张卡片一路输出"设计，但内核还是两路时代的样子：

| 位置 | 旧行为 |
|---|---|
| `AudioEngine.Start(leftDevId, rightDevId, …)` | 只认两台设备 |
| `AudioEngine.Split()` | 固定取 `channel 0/1` |
| `MainForm` 启动快照 | 只把左右两张卡的延迟传下去 |

于是第 3 路起，卡片上的延迟 / 音量 / 静音全部**静默失效**，选 5.1 也只是把前两个声道拆出去。
这不是漏写，是那套泛化内核写在了另一条分支（`main`，11 个提交 / 8546 行）。

---

## 二、移植后的分层

```
界面 (OutputLane 列表: 声道 + 设备 + 延迟 + 音量 + 静音)
        │  LaneRouting.Build()          ← 新增，唯一的翻译入口
        ▼
编辑期模型 (RoutingModel: LogicalChannel 抽头 / ChannelBinding 绑定 / SinkSpec 设备)
        │  Compile(sinks, srcCh)
        ▼
运行时矩阵 (每台设备一张 [输出声道 × 源声道] 矩阵)
        │
        ▼
SinkRuntime × N (延迟线 → 矩阵混音 → 缓冲 → 校正 provider → WasapiOut)
```

- **编辑期三层结构不进逐样本循环**：混音节只看矩阵，`Binding` 越多不会更慢。
- **逻辑声道键 = 界面声道键**（FL/FR/C/LFE/SL/SR/BL/BR/M），抽头由 `RoutingModel.MapOf(srcCh)`
  这张 Windows 扬声器位表决定 —— 界面与内核共用同一张表，不各写一套。

## 三、翻译规则（`src/UI/LaneRouting.cs`）

| 规则 | 内容 | 为什么 |
|---|---|---|
| 一张卡片 = 一台设备 | 同设备的多张卡片在**界面层**就合并成一张多声道卡片：原卡片变成新卡片的行（`p0`/`p1`…） | 同一端点开两条 `WasapiOut` 会互相抢占，其中一路静音；合并后"哪个滑块写端点音量"才有唯一答案 |
| 行 = 物理声道 | 行序就是设备物理声道号（`PhysIndex`）；空行（「（不使用）」）不产生 lane，但**不压缩** `OutChannels` | 行序与物理声道错位只会串音、不会报错，是最难发现的一类问题 |
| 抽头按扬声器位 | FL→s0、FR→s1、C→s2、LFE→s3…；源不够时按前置派生 | 真 5.1 源若按 2 声道上混，后置放的是前置内容，**听着像有声音，所以最难发现** |
| 延迟设备级 | 一台设备一条延迟线，多卡合并时取最小并提示 | 延迟线在混音之前，物理上只能有一个 |
| 音量归属 | 卡片主音量 = 设备端点音量（双向同步 + 停止还原）；多声道各行音量 = 混音增益（乘进矩阵） | 端点音量是设备级单值，只能由主音量承载；行增益按物理声道独立 |
| 形态切换搬音量 | 单→多：主音量继续承载端点，行增益复位 100；多→单：原 `p0` 行增益折进主音量；合并时单声道来源的行增益复位、多声道来源的保留 | 单声道卡片的音量是端点镜像、不是行增益，直接继承会**双份衰减**（12%×12% = 1.44%） |
| 时钟组 | 立体声/单声道规格：所有设备共享 `g0`；多声道规格：每台设备独立 | 送同一对相关声时必须共享 ratio（否则偏音）；拼装拓扑独立可防"个体水位发散 → 设备间相对漂移" |

启动前的 `srcCh` 还不知道（要打开捕获端点才有格式），因此先按立体声建抽头；启动成功后
`ApplyRoutingHot("启动校源")` 用 `AudioEngine.CaptureChannels` 重建一次并 `SetRouting()` 热替换，
真多声道源不会退化成上混。

### 运行中可调的边界（界面置灰规则）

置灰表不是"凭感觉"定的，而是照抄内核能力：`AudioEngine.SetRouting()` 只原子换矩阵，
**设备 / 延迟 / 每路声道数** 都在 `Start` 时定死（`WasapiOut` 与延迟线已建好）。

| 层级 | 控件 | 运行中 | 内核依据 |
|---|---|---|---|
| 采样级 | 增益、主音量/静音、消音、卡片音量/静音、多声道行音量 | 可改 | `SetGain` / `SetMaster` / 端点音量绑定 |
| 矩阵级 | 卡片声道、多声道行声道 | 可改 | `SetRouting` 换矩阵（`SameLinkShape` 通过才换） |
| 形态级 | 「多声道…」 | 单项置灰 + 拦截回滚 | 会改 `OutChannels` → `SetRouting` 明确拒绝（`SinkOutCh != sinks[i].OutCh`） |
| 链路级 | 捕获设备、刷新设备、延迟档位、规格、添加输出、卡片设备/延迟/移除 | 置灰 | 都要重开端点或重建 `WasapiOut` |

实现落点：`MainForm.ApplyUiLock()` 统一分发（状态切换与卡片重建后都调一次），
卡片侧拆成 `SetStructuralLock` / `SetChannelLock` / `SetShapeLock` / `SetVolumeLock`。
「多声道…」是**列表里的一项**，ComboBox 没有"禁用单项"的能力，所以用 `OwnerDrawFixed`
自绘成灰色，并在 `SelectedIndexChanged` 里回滚 + 抛 `ShapeBlocked` 让主窗体记日志。

|---|---|

## 五、验证

### 自动（不需要声卡）

```bat
SplitterGUI.exe --selftest
```

覆盖：两路/两设备、两路/同设备、5.1/三设备、5.1/单块 6ch、2.1、单声道、立体声源上混、
音量归属（端点 1.0 防双衰减 / 非端点 0.5 / 静音 0）、同设备卡片合并（行序 / 行增益复位 / 延迟取最小）、
合并时的音量归属（多声道来源增益保留、单声道来源复位 100）、稀疏物理声道（空行不压缩 `OutChannels`）、
同设备延迟冲突取最小、未分配声道只警告、ini 往返（3 路 / 6 声道 / 延迟 / 行增益）。

### 手工（有设备时）

1. **回归基线**：单声道源 + 两张卡 + 两台设备，听感与日志应与移植前一致
   （`[启动] 预缓冲完成 (L=… R=…)`、`校正=…`、`水位 L=… R=…`）。
2. **第 3 路真的生效**：加第三张卡（换设备或同设备第三声道），启动后
   `[启动] 路由 …: p0←s?` 逐路出现；调它的延迟/音量/静音，日志与听感都有反应。
3. **5.1 分三台设备**：规格切 5.1 → 6 张卡 → 三台设备，日志 `[配置] 路由: … 3 台设备`；
   每台 `2ch`，矩阵为 `p0←s0 p1←s1` / `p0←s2 p1←s3` / `p0←s4 p1←s5`。
4. **单块 5.1 声卡**：6 张卡同一设备 → 合并成一张多声道卡片（6 行），一路 `6ch`，矩阵是单位阵。
5. **多声道卡片**：把某张卡的声道下拉切到「多声道…」→ 卡片变高，按设备物理声道数出现
   `p0`/`p1`… 每行有声道下拉 + 音量条 + 百分比；主音量仍写端点，日志应出现
   `[输出] … 切到多声道: 主音量 12% 仍由设备端点承载, 各行增益复位 100%`（不出现则说明音量被双份衰减）。
   切回单声道 → 行隐藏，日志 `[输出] … 切回单声道: 原 p0 行增益 50% 已折进主音量 → 6%`。
6. **同设备卡片合并**：把第二张卡的设备改成第一张卡的设备 → 两张并成一张多声道卡片，
   日志 `[输出] 同设备的多张卡片已合并为多声道卡片: …` + 每台合并设备一条 `主音量取端点当前值 …%`；
   监听该设备，响度应与合并前一致（端点音量 × 行增益 100%）。
7. **运行中热更新**：运行中改某路「输出声道」/切单多声道/勾静音/拖音量 → `[设置] 路由已热更新`，
   声音不中断；改设备或延迟 → 提示需停止后重新开始。
   - 同时核对置灰：运行中「捕获设备 / 刷新设备 / 延迟档位 / 规格 / 添加输出 / 卡片设备 /
     卡片延迟 / ×」应为灰，声道与各类音量条应为黑可动；声道下拉里「多声道…」应为灰色，
     点击它应回滚并记 `[提示] … 单/多声道形态是链路级参数，运行中不能切换（已还原）`。
8. **异常拦阻**：两路塞进单声道端点 → 启动被 `[路由]` Error 挡住，弹框说明。
9. **音量还原**（`--volprobe` 对照）：
   ```bat
   SplitterGUI.exe --volprobe      :: 开始前: 记下每台设备的端点音量
   ```
   开始分流 → 卡片音量写到端点（`[启动] 按UI值写入端点: …`）→ 停止 →
   日志应逐台出现 `[还原] 左前 扬声器 (9- Xiaomi …): 音量 12% → 20%（未静音）`，
   再跑一次 `--volprobe`，端点值应与开始前一致。
   若出现 `[警告] … 设备未接受该写入`，说明是设备/驱动侧不接受（量化档位或只读），
   程序侧已留存基线并在下次停止时重试，不是还原逻辑没跑。

## 五点五、音量还原的语义（按设备）

| 时机 | 行为 |
|---|---|
| 开始分流 | 每台"独占一台设备"的卡：记录该设备**当时**的音量/静音为基线，然后按 UI 值写入 |
| 停止 / 启动失败 / 退出 | 写回基线，逐台打印 `[还原] …`；回读确认，不一致则保留基线待重试 |
| 运行中换设备 / 删卡 / 加卡 | 被弃设备的音量**当场还原**；新设备按 UI 值绑定写入（`[变更] 输出设备已变…`） |
| 同设备（已合并成一张多声道卡片） | 端点是设备级单值 → 只有卡片**主音量**写它（唯一归属，有基线可还原）；各行音量走混音增益 |
| 基线生命周期 | 成功还原（回读一致）才删除；中途重绑沿用旧基线，绝不用"自己写进去的值"当基线 |

## 六、已知边界（本次未做）

1. **「极限」档位欠载**：`DriftTargetMs` 仍只按 `max(pre,out)+余量` 算，没有考虑捕获端一次回调
   送多大一块。HDMI 这类 ~40ms 整块到达的端点，在 45ms 目标水位下会周期性见底
   （36/36 个 30s 窗口全部越界）。修法：按实测块时长抬高目标 + 把欠载判据从"水位深度"
   改成"连续 N 次取不到数据"。**与本移植正交，可单独改。**
2. **延迟/设备变更需重启**：`SinkRuntime` 的延迟线与 `WasapiOut` 都在启动时固定，热替换只换矩阵。
3. **设备级延迟粒度**：延迟按设备取最小（合并卡片时一并合并了这条控制），已不再是"界面看不到"的问题；
   但真要让同设备的每个物理声道各有延迟，需要内核按声道拆延迟线。
4. **`Routing.Config.cs` 暂未接界面**：ini 仍是 `Out{n}.*`，路由 schema 目前供自检/外部配置使用；
   将来若要"用文本描述整套路由"，从这里接。
