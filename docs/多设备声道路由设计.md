> 版本：v1.0　编制日期：2026-11-15

> 前置文档：`docs/修改方案.md`（行为契约）、`docs/修改计划-v1.1.md`、`docs/回归测试清单.md`

## 0. 摘要

| 需求 | 实现手段 | 改动面 |
|---|---|---|
| 同时连接多台输出设备 | 引擎内 `left/right` 两个字段泛化为 `List<SinkRuntime>`，每路独立 `BufferedWaveProvider` + `WasapiOut` | `AudioEngine` 重写为 N 路主循环 |
| 每设备独立声道路由 | 每路一个 `ChannelMap`（输出声道 → 若干 `源声道 × 增益`），混音在捕获回调里按路完成 | 新增 `ChannelMap` / `SinkRouter`，替换 `Split()` |
| 立体声 / 5.1 / 7.1 映射 | 预设矩阵（mono / stereo / upmix 5.1 / upmix 7.1 / downmix 5.1 / downmix 7.1 / custom） | 新增 `ChannelPresets` |
| 单独启用 / 禁用某设备 | 禁用 = 不建该路链路（不占缓冲、不参与预缓冲判定、不参与看门狗） | 引擎 `SetSinkEnabled`，启动门槛改为"所有启用路达标" |
| 设备变化时配置有效 | 配置按 `DeviceId` 存 + 名称二级匹配；缺失时保留条目并标红，不影响其他路 | 新增 `SinkResolver`，`DefaultChangeWatcher` 增加 `OnDeviceAdded` |
| 不破坏现有偏音修复 | `DriftCorrectionShared` 升级为 `ClockGroup`（成员集合），默认前两路同组，行为与当前完全等价 | 改名 + 成员表，公式不变 |

**核心约束（必须先对齐）**：输出声道数**不由软件决定**，由端点的混音格式（`IAudioClient::GetMixFormat`）决定。用户要 5.1/7.1 输出，必须先在「Windows 设置 → 声音 → 该设备 → 配置扬声器」里设成 5.1/7.1，端点才会以 6/8 声道混音。软件能做的是：读取实际声道数，把 N 个输出声道逐个映射到捕获源的任意声道。详见 §2.2。

## 1. 现状与硬编码假设

当前链路（`AudioEngine.Start`）：

```
WasapiLoopbackCapture(系统默认输出, srcFmt: 48k/f32/N ch)
  └ DataAvailable → leftLine.Write / rightLine.Write
        └ Split(buf, off, len, channel=0|1, leftBuf|rightBuf)   // 取单个源声道 → mono float
              └ DriftCorrectingProvider(mono, 单声道 ring 64 帧)
                    └ WasapiOut(dev, Shared, true, outMs)         // mono float 输出
```

现存的"两路"硬编码共 9 处，是本次改造的清单：

| # | 位置 | 硬编码 | 改造后 |
|---|---|---|---|
| 1 | `AudioEngine` 字段 | `leftOut/rightOut`、`leftBuf/rightBuf`、`leftProv/rightProv`、`leftDev/rightDev` | `List<SinkRuntime> sinks` |
| 2 | `Start` 参数 | `leftDevId, rightDevId, leftDelayMs, rightDelayMs` | `AudioEngineOptions.Sinks[i].DeviceId/DelayMs` |
| 3 | `Split(...)` | 单声道抽取 + `channel % ch` | `SinkRouter.Process`（矩阵混音） |
| 4 | 输出格式 | `CreateIeeeFloatWaveFormat(rate, 1)` | 端点 mix format（声道数/采样率以端点为准） |
| 5 | `DriftCorrectingProvider` | 单声道 ring `float[64]`、`prev` 单值 | `float[ch][64]`、`prev[ch]`，phase 仍按帧共享 |
| 6 | `DriftCorrectionShared` | `errLeft/errRight`、`OtherHolding(isLeft)` | `Dictionary<string,double> errs`、`AnyOtherHolding(key)` |
| 7 | 预缓冲 | `leftBuf.BufferedBytes < fillBytes \|\| rightBuf...` | 遍历启用路，各自 fillBytes |
| 8 | 看门狗 | `LeftRenderedSamples/RightRenderedSamples`、`SharedRatioPpm` | `SinkStatuses[]` + 组 ratio |
| 9 | `ChannelBindingSet` | `Master/Left/Right` 三个固定槽位 | `Dictionary<string, EndpointVolumeBinding>` |

另有一处隐含假设：**所有输出与捕获同采样率**。当前 `targetSamples` 直接用捕获采样率，provider 的 `phase += ratio` 默认 1.0 帧/输出帧。跨采样率的实际可行性已实测（见 §6.1、§6.3）：系统会自动转换，v1 不需要自己重采样。

## 2. 能力边界（先划清，避免实现后返工）

### 2.1 能做到

- 最多 8 台输出设备同时出声，各自独立音量、静音、延迟补偿（0~2000ms）、启用开关
- 每台设备的输出声道逐个路由：`输出声道 j ← Σ(源声道 k × 增益)`，可为静音
- 从 2 声道捕获源上混到 5.1/7.1；从 5.1/7.1 捕获源下混到立体声；从 5.1 源单取某一声道（如只要中置的人声）
- 设备拔插后配置保留；ID 变了按名称重新绑定；同一时刻只丢受影响的那一路
- 运行时单路启停，不打断其他路

### 2.2 做不到（且不应假装能做）

| 限制 | 原因 | 代替方案 |
|---|---|---|
| 软件里选"7.1"就让 2 声道设备变 7.1 | 实测（§6.3）：客户端声道数**大于**端点 mix 声道数时 `WasapiOut.Init` 直接抛 `ArgumentException: 尚未实现`（NAudio 把 `AUDCLNT_E_*` 映射成了这句话）。mix 声道数来自 Windows 的"配置扬声器" | 先在 Windows 里把该设备设为目标布局；软件启动前校验并给出人话提示 |
| 用独占模式自定义任意格式 | 项目已删除独占模式（USB 设备标称 48k 实测偏差约 10%，远超校正环 ±0.5%） | 不做 |
| 多台设备之间的绝对同步 | 各设备晶振独立，校正环只能各自把水位拉回目标，不能建立共同时间基准 | 同一 `ClockGroup` + 手动 `DelayMs` 对齐到 ±1ms 级；跨组不保证 |
| 每台设备独立捕获 | loopback 只能捕获"系统默认输出"这一路 | 用虚拟声卡做多路分发，或接受单捕获源 |
| LFE 真低通 | 需要 4 阶 Linkwitz-Riley，成本与本需求不匹配 | LFE 默认取 `(L+R)×0.35` 或静音，文档标注"非标准 LFE" |
| 上混不削波 | 矩阵求和可能超过 1.0 | provider 现有硬限幅 + 预设系数留 3~6dB 余量 |

## 3. 目标数据流

```
WasapiLoopbackCapture(默认输出, srcFmt)
  │  DataAvailable(buf, len)
  ├─► SinkRuntime[0].Consume(buf, len)
  │      SinkRouter(map0) → 交错 float[frames × ch0]
  │      → DelayLine(delay0) → Buf0(outFmt0)
  │      → DriftCorrectingProvider(ch0, groupA) → WasapiOut(dev0, outFmt0)
  ├─► SinkRuntime[1].Consume(buf, len)
  │      SinkRouter(map1) → ... → WasapiOut(dev1, mixFmt1)
  └─► SinkRuntime[n] ...（禁用路不在列表里，零开销）

捕获线程：一次读取，N 次混音（push 模型，与现有一致）
输出线程：每路一条 WASAPI 线程，各自拉自己的 Buf（pull 模型，与现有一致）
```

关键点：**混音必须在每路各自的延迟线之前**，因为每路 `DelayMs` 不同。混音结果按路缓存在复用数组里，不进堆分配（沿用现有 `splitOut/splitF` 的复用思路）。

## 4. 配置项设计

### 4.1 ini schema

沿用 `SplitterGUI.ini`（`SettingsStore`，键值 + 插入顺序 + 原子写）。新增键全部带 `Sink{n}.` 前缀，`n` 从 0 递增、**删除后不重排**（避免下游索引错位）。

| 键 | 类型 | 范围 | 默认 | 说明 |
|---|---|---|---|---|
| `SinkCount` | int | 1~8 | 2 | 配置的路数（含禁用路） |
| `Sink{n}.Key` | string | `s0`~`s7` | 自动 | 稳定标识，运行期事件/日志用；与 n 解耦，便于将来重排 |
| `Sink{n}.DeviceId` | string | endpoint ID | 空 | 主匹配键 |
| `Sink{n}.Name` | string | 任意 | 空 | 友好名缓存，ID 失配时二级匹配 + UI 显示 |
| `Sink{n}.Enabled` | 0/1 | | 1 | 0 = 不建链路 |
| `Sink{n}.Label` | string | ≤12 字 | `左`/`右`/`设备n` | 用户命名，日志前缀与状态行用 |
| `Sink{n}.DelayMs` | int | 0~2000 | 0 | 该路延迟补偿（混音后） |
| `Sink{n}.Volume` | int | 0~100 | 100 | 采样层音量（与端点音量双向绑定） |
| `Sink{n}.Mute` | 0/1 | | 0 | 采样层静音 |
| `Sink{n}.Preset` | enum | 见 §4.3 | `mono-left`/`mono-right` | 预设名；`custom` 时才读 `Map*` |
| `Sink{n}.Channels` | int | 1~8 | 端点实际值 | 保存时的输出声道数，用于回读时判断是否需要重新拟合 |
| `Sink{n}.Map{j}` | string | `src*gain,src*gain` \| `mute` | 依预设 | 第 j 个输出声道的抽头表 |
| `Sink{n}.ClockGroup` | string | `g0`~`g3` \| 空 | 前两路 `g0`，其余空 | 校正组；空 = 独立 ratio |

其余沿用现有键（`LatencyProfile`、`Gain`、`VolumeMaster`、`MuteCapture`、`DriftMode`、`FixedRatioPpm`、`WaterIntervalSec`、`MinimizeToTray`、`DeviceDefault`）。`DeviceLeft` / `DeviceRight` 保留写入（旧版可回退），读取时作为 `Sink0/Sink1` 的兜底来源。

### 4.2 Map 语法

```
Map{j}  := tap ( "," tap )*
tap     := srcIdx "*" gain
特殊值  := "mute" | ""   → 该输出声道静音
```

- `srcIdx` 越界（源只有 2ch 却写 `2*1.0`）→ 启动时按 `srcIdx % srcCh` 折叠并记一条日志（保留旧版"单声道捕获时取模回 ch0"的行为）
- `gain` 容许 0.0~2.0，总和 >1 时由 provider 的硬限幅兜底，但预设自身留余量
- 空 tap 列表 = 静音（用于 LFE 无声卡）

### 4.3 预设与系数

| Preset | 输出声道 | 定义（`L`=src0, `R`=src1, `FL/FR/C/LFE/SL/SR` 从 6ch 源按序取） | 说明 |
|---|---|---|---|
| `mono-left` | 1 | `0*1.0` | 现行为：只取源 ch0 |
| `mono-right` | 1 | `1*1.0`（源单声道时折回 0） | 现行为 |
| `stereo` | 2 | `0*1.0`, `1*1.0` | 源 ≥2ch 直通前两声道 |
| `stereo-mono` | 2 | `0*0.707,1*0.707` ×2 | 双声道都放混合单声道（单只音箱场景） |
| `upmix-5.1` | 6 | `FL=L, FR=R, C=0.5L+0.5R, LFE=0.35L+0.35R, SL=0.7L, SR=0.7R` | 从立体声扩展；C 用 0.5 而非 0.707 防削波 |
| `upmix-7.1` | 8 | 同上 + `BL=0.7L, BR=0.7R`（SL/SR 用 0.5） | 侧/后分离 |
| `downmix-5.1` | 2 | `0*1.0,2*0.707,4*0.5` / `1*1.0,2*0.707,5*0.5` | 标准下混近似，LFE 丢弃 |
| `downmix-7.1` | 2 | 同上 + 后环绕 ×0.5 | |
| `bridge-31` | 3 | `L, R, C=0.5L+0.5R` | 常见 3.1/3.0 声卡 |
| `custom` | 任意 | 读 `Map{j}` | |

系数说明：上混/下混系数取工程常用近似（非 Dolby/DTS 授权系数），目的是"声场合理、不削波"，不追求标准兼容。

### 4.4 迁移与校验

- **旧配置**（无 `SinkCount`）：`DeviceLeft`/`DeviceRight` → `Sink0/Sink1`，Preset 分别 `mono-left`/`mono-right`，`ClockGroup=g0`，`Enabled=1`。行为与当前**逐字节等价**（同一 `Split` 语义、同一 ratio 共享）
- **新写旧读**：`DeviceLeft`/`DeviceRight` 始终同步为 `Sink0/Sink1` 的 DeviceId，旧版仍可启动；新键被旧版忽略
- **启动前校验**（不通过则拒绝启动并给出人话原因）：
  1. 至少 1 路 `Enabled`
  2. 启用路之间 DeviceId 不得重复（同一端点开两个 `WasapiOut` 会互相抢占，实测表现为其中一路静音）
  3. 任一路 DeviceId 不得等于捕获设备（回环）
  4. 每路 `Channels` 与端点实际声道数不一致时**不拒绝**，按实际值重新拟合并记日志

## 5. 接口设计

全部 `internal`（项目无 `public` API 诉求），命名风格沿用现有类。

### 5.1 数据模型

```csharp
namespace StereoSplitter.Audio
{
    /// 单个抽头: 输出声道取哪个源声道、乘多少增益
    struct ChannelTap
    {
        public int Src;        // -1 = 静音
        public float Gain;
    }

    /// 输出声道 → 抽头组。"一个输出声道可以由多个源声道叠加"
    sealed class ChannelMap
    {
        public int OutChannels { get; }
        public ChannelTap[][] Taps { get; }        // [outCh][0..3]

        public ChannelMap(int outChannels);
        public static ChannelMap FromPreset(string preset, int srcCh, int outCh);
        public static ChannelMap FromIni(int outCh, Func<int, string> getValue);
        public string ToIni(int outCh);

        /// 端点声道数变化时重新拟合: 多余截断, 不足补静音
        public ChannelMap FitTo(int outChannels);
        /// 源声道数变化时折叠越界抽头 (srcIdx % srcCh)
        public ChannelMap FitSource(int srcChannels);
        public bool IsSilent(int outCh);
    }

    /// 一路输出的静态配置 (来自 ini, 不改动)
    sealed class SinkConfig
    {
        public string Key;            // "s0"
        public string DeviceId;
        public string CachedName;
        public string Label;          // "左"
        public bool Enabled;
        public int DelayMs;
        public int Volume;
        public bool Mute;
        public string Preset;
        public ChannelMap Map;        // Preset=custom 时来自 Map*
        public string ClockGroup;     // null/"" = 独立
    }
}
```

### 5.2 路由（纯函数，无状态，可单测）

```csharp
sealed class SinkRouter
{
    public SinkRouter(ChannelMap map, int srcChannels);

    public int OutChannels { get; }

    /// 输入交错 float (srcChannels 声道) → 输出交错 float (OutChannels 声道)
    /// dst 长度必须 >= frames * OutChannels, 由调用方复用
    public void Process(float[] src, int srcOffset, int frames, float[] dst);

    /// 字节 → float 的解交错 (与现有 Split 的三种格式分支一致)
    public static void ToInterleaved(byte[] data, int offset, int bytes, WaveFormat fmt, float[] dst);
}
```

职责分离的意义：`Process` 是纯数学，可以用固定输入断言输出，不像现在 `Split` 同时管格式解析、声道取模、缓冲写入三件事。

### 5.5 时钟组（由 `DriftCorrectionShared` 演进）

```csharp
sealed class ClockGroup
{
    public ClockGroup(string id, double targetSamples, int sampleRate, Action<string> log);
    public string Id { get; }
    public int MemberCount { get; }

    public void Update(string sinkKey, double smoothedTotal);  // 提交各自的平滑水位
    public void NotifyHolding(string sinkKey, bool holding);
    public bool AnyOtherHolding(string sinkKey);

    public float Ratio { get; }
    public double RatioPpm { get; }
}

sealed class ClockGroupSet
{
    public ClockGroup Get(string groupId);   // null/"" → 每路一个独立组
    public void UpdateTarget(double targetSamples, int sampleRate);  // 采样率变化时
}
```

公式完全沿用现状：`avgErr = mean(errs)`、`r = 1 + kpNow*avgErr`、`|r-1| ≤ 0.005`、`fastGain` 切换阈值与 `updates` 计数由 `MemberCount` 归一（`SwitchAfterUpdates * MemberCount`，保持约 128 秒的时间常数）。`MemberCount==2` 时与原实现**数值等价**。

`Bind` 内部沿用现有 `Rebind` 的三段式（同设备复用 / 换设备先还原静音再释放 / 空 ID 解绑），只是 key 从"左/右"变成 sink key。


## 6. 与现有逻辑的兼容方式

逐条对照，每条都给出"不改会怎样"，避免实现时漏项。

| 现有逻辑 | 兼容做法 | 不改的后果 |
|---|---|---|
| **偏音修复**（shared ratio） | `ClockGroup` 成员集合，前两路默认同组。`MemberCount=2` 时公式与现实现逐值相同 | 若每路独立 ratio，左右两台设备插值方向不对称，偏音回归 |
| **holding 联动**（-6dB） | `AnyOtherHolding(key)` 只在组内、且组内成员 >1 时生效；单路组恒为 false | 5.1 单设备场景会把自己的 6 个声道当成"对侧"，一路欠载就把整机降 6dB |
| **`Split()` 单声道抽取** | 由 `mono-left/right` 预设表达，`channel % ch` 折叠逻辑移进 `FitSource` | 源为单声道时越界读 → 进程被杀（现有注释已记录这个坑） |
| **`DelayLine`** | 每路一条，混音后按该路 `DelayMs` 建；`BytesOf(wf, ms, blockAlign)` 用该路输出格式 | 用捕获格式算字节数会让 6ch 输出的延迟只有 1/6 |
| **预缓冲**（`fillBytes` 等待） | 遍历启用路，各自 `fillBytes = fillTargetSamples * outCh * 4`；超时上限取 `max(各路 fillMs + delayMs) + 1000` | 只等两路会让慢设备（蓝牙）起播即欠载 |
| **修剪**（`TrimTo`） | 逐路 `TrimToFill()`，统一修剪到各自 fillBytes | 快路多攒的水位抵消延迟线时差，延迟补偿失准 |
| **输出缓冲溢出告警** | 告警带 `Label`，60 秒/路限流 | 多路共用一条限流会吞掉真正出问题那一路 |
| **看门狗停摆** | 逐路 `RenderedSamples`，冻结 10 秒 → 只重建该路（`SetSinkEnabled` 循环） | 一路休眠导致整体重启，正在播的其他路被硬切 |
| **看门狗失衡** | 判据从"左/右 vs 组内平均"推广为"某路调节水位 > 300ms 且组 ratio 触顶 > 10 秒" | 5.1 设备里只有一路失配时检不出来 |
| **`WasapiOut` 生命周期** | 每路独立 `PlaybackStopped` → `SinkFailed(key, why)`；`stopping` 标志仍屏蔽主动停止 | 单路停止会被当成整机故障 |
| **端点音量双向绑定** | `VolumeBindingSet` 按 key 管理；UI 每行滑条绑自己的 key | `Master/Left/Right` 固定槽位无法表达第 3 路 |
| **UI 值权威写回** | `WriteValues` 遍历启用路 | 新增路启动时音量取端点旧值，与 UI 不一致 |
| **`RestoreDefaultOutput`** | 不变（捕获端仍是单路） | 停止后系统默认卡在虚拟声卡 → 全部无声 |
| **自动重建**（`MaxAutoRestart`） | 捕获端故障 → 全链路重建；单路故障 → 只重建该路，不消耗整体重试额度 | 一路坏掉把整体重试次数耗光，最后 `GiveUp` |
| **单实例 / 托盘 / 前台激活** | 不变 | — |
| **`Program` 内嵌 NAudio 解析** | 不变（未新增程序集依赖） | — |

### 6.1 采样率不一致（实测已可免费解决）

`WasapiOut` 在共享模式下给了 NAudio 一个"自动转换"路径：实测把 44.1k / 96k / 16bit provider 交给 48k 端点，`Init` 全部成功（`IsFormatSupported` 却报 no）。说明 NAudio 在 `Initialize` 时带了 `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY`，由 Windows 音频引擎做采样率与位深转换。

因此 v1 的取向是**不自己重采样**：`provider.WaveFormat` 的采样率直接用捕获源采样率，采样率差交给系统 SRC。好处是零新增代码、零新增缓冲；代价是系统 SRC 的延迟（几毫秒）与音质不可控，且与漂移校正叠加时无法精确建模。

若后续要精确（v2，可选）：`DriftCorrectingProvider` 增加 `baseRatio = (double)srcRate / dstRate`，`phase += baseRatio * ratio`，让校正环直接工作在端点采样率上。

- `baseRatio` 偏离 1 在 ±10% 内时 Catmull-Rom 的混叠落在 21kHz 以上，可接受（48k↔44.1k 为 0.919/1.088）
- 偏离超过 10%（96k → 44.1k）才改用 `WdlResamplingSampleProvider` 前置转换
- 水位换算：`BufferedBytes / (4 * outCh)` 得帧，除以采样率得毫秒 —— 与延迟线的毫秒口径天然一致，**不受是否走系统 SRC 影响**（时间轴相同）

### 6.2 上混的削波

矩阵求和 `Σ gain` 可能 >1。三层防护：预设系数留余量（最大和 1.4，但只在极端同相信号下触顶）→ provider 现有 `if (v > 1f) v = 1f` 硬限幅 → 日志在单路连续限幅时记一条（新增计数器，限流 60 秒）。

### 6.3 格式协商实测（本机 8 个活动端点，2026-11-15）

本机全部端点的 mix format 均为 `48000Hz / Extensible / 32bit / 2ch / sub=IEEE_FLOAT`，因此 5.1/7.1 三条路径**无法在本机验证**，P4 需要在有 5.1 端点的机器上复测。

| provider 格式 | IsFormatSupported(Shared) | WasapiOut.Init | 结论 |
|---|---|---|---|
| f32 1ch @48k（少于端点声道） | no | **ok** | 系统自动上混到 2ch |
| f32 2ch @48k（= mix format） | yes | **ok** | 原生路径 |
| f32 2ch @44.1k / @96k | no | **ok** | 系统 SRC 转换 |
| pcm16 2ch @48k | yes | **ok** | 位深转换可用 |
| f32 6ch @48k（多于端点声道） | no | **ArgumentException: 尚未实现** | 客户端声道数不得大于端点声道数 |
| f32 8ch @48k | no | 同上 | 同上 |

三条落地结论：

1. **`OutChannels = min(端点 mix 声道数, 目标布局声道数)`**，启动前校验，超了就拒绝并提示"该设备端点为 2.0，请先在 Windows 里配置为 5.1/7.1"
2. 报错文案必须自己翻译：`ArgumentException: 尚未实现` 对用户毫无意义，映射成"设备声道配置不匹配"
3. 因为 `IsFormatSupported` 会给出误导性的 `no`，**不要用它做启动门槛**，直接 `Init` + 捕获异常更准

## 7. 设备变化时保持配置有效

三层保障，缺一层就会丢配置：

1. **存储层**：配置按 `DeviceId`（endpoint ID，Windows 分配后稳定）+ `CachedName` 双写。ID 变化时名称兜底，名称变化时 ID 兜底，两者都变才需要人工重选
2. **解析层**：`SinkResolver` 每次启动/刷新都重新解析，匹配成功即把新 ID 回写 `SinkConfig`（并记日志"设备 ID 已更新"），配置条目永不因失配被删除
3. **事件层**：`DefaultChangeWatcher` 增加 `OnDeviceAdded(deviceId)` 回调 → 若有 `NotFound` 的路其名称与新增设备匹配，自动补建该路

运行时行为矩阵：

| 事件 | 现有行为 | 新行为 |
|---|---|---|
| 某路设备被拔 | 整体 `OnEngineStalled` → 全量重建 | 该路 `SinkFailed` → 只停该路，标 `Healthy=false`，其余继续；配置保留 |
| 某路设备插回 | 不自动恢复（需手动开始） | `OnDeviceAdded` 匹配成功 → 自动补建该路，填满预缓冲后渐入 |
| 捕获设备（系统默认）变化 | 全链路重建 | 不变（捕获格式可能变，必须整体重建） |
| 用户刷新设备 | 重建下拉，按 ini 恢复选中 | 重建列表，逐路重新解析，标红不存在的路 |
| 用户换 USB 口（ID 变） | 找不到 → 静默回退到索引 0 | 名称匹配成功 → 自动绑定，日志说明 |

## 8. 运行时启用 / 禁用

- **禁用**：`sink.Enabled=false` → `Stop()` + `Dispose()` 该路（释放 `WasapiOut`、`MMDevice`、`DelayLine`、`BufferedWaveProvider`），从 `sinks` 列表移除。资源占用归零，看门狗不再看它
- **启用**：新建该路 → 填到 `fillBytes` → `Play()`。为避免"从 0 水位起播"的咔哒，采用 3ms 淡入（provider 已有 `fadeIn` 机制，起播时置 0 即可复用）
- **不影响其他路**：`ClockGroup` 成员数变化会改变 `SwitchAfterUpdates` 归一系数，但 `ratio` 与 `kpNow` 连续保持，不重置（否则组内水位会突跳）
- **UI 约束**：运行中允许改 `Enabled`、`Volume`、`Mute`、`DelayMs`（重建该路延迟线）、`Map`（重算路由）；**不允许**改 DeviceId（需停止后改，避免端点切换时的 COM 竞态）

## 11. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 用户以为"选 7.1 就变 7.1" | 功能预期落空 | UI 在设备行直接显示"端点实际 6ch"，映射对话框顶部写清前提 |
| 多路共享 ratio 在 3+ 路时收敛变慢 | 水位恢复慢 | `SwitchAfterUpdates` 按成员数归一；组内 >4 路时建议拆组 |
| 蓝牙多设备同时连接带宽不足 | 断续、爆音 | 启动前检测：若 >2 路蓝牙，提示"建议只保留 1~2 路蓝牙，其余用有线" |
| 上混系数导致削波 | 破音 | 预设留余量 + 硬限幅 + 限幅计数日志 |
| 单路重建时 COM 竞态 | 偶尔 `E_NOINTERFACE` | 沿用现有约束：`MMDevice` 只在引擎线程创建/释放，UI 只传 ID |
| 内存随路数线性增长 | 8 路 6ch ≈ 9MB | 可接受；`BufferDuration` 从 1000ms 收到 600ms 可减半（需重算 drift 余量） |

## 12. 不做清单

- 不做独占模式（历史原因：USB 标称/实测采样率偏差 10%，参见 `b83fdfa` 前的实验）
- 不做每设备独立 loopback 捕获
- 不做 ASIO / 内核流
- 不做跨设备采样级同步（无共同时钟源，做不到）
- 不做 LFE 低通滤波
- 不做环绕声编码（Dolby/DTS bitstream 直通）
