## 0. 摘要

| 需求 | 实现手段 | 改动面 |
|---|---|---|
| 同时连接多台输出设备 | 引擎内 `left/right` 两个字段泛化为 `List<SinkRuntime>`，每路独立 `BufferedWaveProvider` + `WasapiOut` | `AudioEngine` 重写为 N 路主循环 |
| 每设备独立声道路由 | 每路一个编译后的矩阵（输出声道 → 若干 `源声道 × 增益`），混音在捕获回调里按路完成 | 新增 `RoutingModel.Compile()` / `SinkRouter`，替换 `Split()` |
| **5 种工作模式可选** | `split-lr` 左右分离 / `mirror-stereo` 同源并播 / `surround` 拼装环绕 / `mono-broadcast` 单声广播 / `custom` 自定义；模式只负责生成默认清单与绑定 | 新增 `ModeStripControl` + `ApplyModeTemplate()` |
| **多台设备共用同一声道** | 同一逻辑声道挂多条 `Bind`（不同设备/物理声道），折叠后各自矩阵里都有它 | 无特殊机制，矩阵天然支持 |
| **声道数可视化与手动增删** | 横向卡片带，一张卡 = 一个逻辑声道，三行固定显示「名称 / 源抽头 / 承接设备」；改任一处三处联动刷新 | 新增 `ChannelStripControl` / `ChannelCardControl` |
| 立体声 / 5.1 / 7.1 映射 | 预设矩阵（mono / stereo / upmix 5.1 / upmix 7.1 / downmix 5.1 / downmix 7.1 / custom） | 新增 `ChannelPresets` |
| 单独启用 / 禁用某设备 | 禁用 = 不建该路链路（不占缓冲、不参与预缓冲判定、不参与看门狗） | 引擎 `SetSinkEnabled`，启动门槛改为"所有启用路达标" |
| 设备变化时配置有效 | 配置按 `DeviceId` 存 + 名称二级匹配；缺失时保留条目并标红，不影响其他路 | 新增 `SinkResolver`，`DefaultChangeWatcher` 增加 `OnDeviceAdded` |
| 不破坏现有偏音修复 | `DriftCorrectionShared` 升级为 `ClockGroup`（成员集合）；`mono-left/right` 预设下前两路同组，行为与当前完全等价；拼装预设下每路独立组 | 改名 + 成员表，公式不变 |

**核心约束（已按选定拓扑修订）**：实际用法是**多台立体声设备拼装**（每台只出 2 声道），所以：

- 输出声道数 = 设备台数 × 2，**不需要**去 Windows「配置扬声器」改任何布局；端点永远是 2ch，`WasapiOut.Init` 必然成功
- 真正的门槛在**声源侧**：系统只有 2 声道端点时 loopback 也只有 2 声道，要拿到 6 声道必须先把 VB-CABLE 配成 5.1 并设为默认输出（或用矩阵上混合成）
- **每路必须独立时钟组**：共用一个 ratio 会让设备间水位发散 → 延迟漂移 → 对齐失效。相关声对固定在单台设备内，偏音问题不存在

详见 §2.3；标定流程见 §7.1。

## 1. 现状与硬编码假设

当前链路（`AudioEngine.Start`）：

```
WasapiLoopbackCapture(系统默认输出, srcFmt: 48k/f32/N ch)
  └ DataAvailable → leftLine.Write / rightLine.Write
        └ Split(buf, off, len, channel=0|1, leftBuf|rightBuf)   // 取单个源声道 → mono float
              └ DriftCorrectingProvider(mono, 单声道 ring 64 帧)
                    └ WasapiOut(dev, Shared, true, outMs)         // mono float 输出
```

现存的"两路"硬编码共 9 处，是本次改造的清单：

| # | 位置 | 硬编码 | 改造后 |
|---|---|---|---|
| 1 | `AudioEngine` 字段 | `leftOut/rightOut`、`leftBuf/rightBuf`、`leftProv/rightProv`、`leftDev/rightDev` | `List<SinkRuntime> sinks` |
| 2 | `Start` 参数 | `leftDevId, rightDevId, leftDelayMs, rightDelayMs` | `AudioEngineOptions.Sinks[i].DeviceId/DelayMs` |
| 3 | `Split(...)` | 单声道抽取 + `channel % ch` | `SinkRouter.Process`（矩阵混音） |
| 4 | 输出格式 | `CreateIeeeFloatWaveFormat(rate, 1)` | 端点 mix format（声道数/采样率以端点为准） |
| 5 | `DriftCorrectingProvider` | 单声道 ring `float[64]`、`prev` 单值 | `float[ch][64]`、`prev[ch]`，phase 仍按帧共享 |
| 6 | `DriftCorrectionShared` | `errLeft/errRight`、`OtherHolding(isLeft)` | `Dictionary<string,double> errs`、`AnyOtherHolding(key)` |
| 7 | 预缓冲 | `leftBuf.BufferedBytes < fillBytes \|\| rightBuf...` | 遍历启用路，各自 fillBytes |
| 8 | 看门狗 | `LeftRenderedSamples/RightRenderedSamples`、`SharedRatioPpm` | `SinkStatuses[]` + 组 ratio |
| 9 | `ChannelBindingSet` | `Master/Left/Right` 三个固定槽位 | `Dictionary<string, EndpointVolumeBinding>` |

另有一处隐含假设：**所有输出与捕获同采样率**。当前 `targetSamples` 直接用捕获采样率，provider 的 `phase += ratio` 默认 1.0 帧/输出帧。跨采样率的实际可行性已实测（见 §6.1、§6.3）：系统会自动转换，v1 不需要自己重采样。

## 2. 能力边界（先划清，避免实现后返工）

### 2.1 能做到

- 最多 8 台输出设备同时出声，各自独立音量、静音、延迟补偿（0~2000ms）、启用开关
- 每台设备的输出声道逐个路由：`输出声道 j ← Σ(源声道 k × 增益)`，可为静音
- 从 2 声道捕获源上混到 5.1/7.1；从 5.1/7.1 捕获源下混到立体声；从 5.1 源单取某一声道（如只要中置的人声）
- 设备拔插后配置保留；ID 变了按名称重新绑定；同一时刻只丢受影响的那一路
- 运行时单路启停，不打断其他路
- 5 种工作模式一键切换（左右分离 / 同源并播 / 拼装环绕 / 单声广播 / 自定义），切换后清单与绑定自动就位，可继续手改
- 同一逻辑声道同时送往多台设备（多房间同播、两副耳机、同空间并联补声），每条绑定独立增益
- 逻辑声道数 1~16 手动增删，声道清单可视化，未分配 / 冲突 / 离线三种状态在卡片上一眼可见

### 2.2 做不到（且不应假装能做）

| 限制 | 原因 | 代替方案 |
|---|---|---|
| 软件里选"7.1"就让 2 声道设备变 7.1 | 实测（§6.3）：客户端声道数**大于**端点 mix 声道数时 `WasapiOut.Init` 直接抛 `ArgumentException: 尚未实现`（NAudio 把 `AUDCLNT_E_*` 映射成了这句话）。mix 声道数来自 Windows 的"配置扬声器" | 拼装拓扑用不到（§2.3.1）：每台设备只吃 2 声道，端点始终 2ch。真要走单端点 7.1 才需要先在 Windows 里改该设备布局 |
| 用独占模式自定义任意格式 | 项目已删除独占模式（USB 设备标称 48k 实测偏差约 10%，远超校正环 ±0.5%） | 不做 |
| 多台设备之间的绝对同步 | 各设备晶振独立，无法建立共同时间基准；只有"各自锁住自己的缓冲水位"这一条路（见 §2.3） | 每路独立时钟环 + 一次性 `DelayMs` 标定，稳态对齐可维持；起播瞬间仍可能差几十 ms，靠淡入掩盖 |
| 每台设备独立捕获 | loopback 只能捕获"系统默认输出"这一路 | 用虚拟声卡做多路分发，或接受单捕获源 |
| LFE 真低通 | 需要 4 阶 Linkwitz-Riley，成本与本需求不匹配 | LFE 默认取 `(L+R)×0.35` 或静音，文档标注"非标准 LFE" |
| 上混不削波 | 矩阵求和可能超过 1.0 | provider 现有硬限幅 + 预设系数留 3~6dB 余量 |

---

### 2.3 选定拓扑：多台立体声设备拼 5.1 / 7.1

已确认的实际用法是**每台设备只出 2 个声道，N 台拼成 N×2 声道**（不是"一台 5.1 声卡出全部声道"）。这个选择让一处限制消失、两处设计需要改。

#### 2.3.1 端点始终是 2 声道，P4 的最大障碍自动消失

§6.3 实测的 `6ch/8ch → ArgumentException: 尚未实现`，只在"单个端点要吃 6 声道"时出现。每台设备只吃自己的那 2 个声道，端点格式永远是系统默认的 2ch/48k：

- **不需要**去 Windows「配置扬声器」里改任何设备的布局
- 客户端声道数 = 端点声道数 = 2，`WasapiOut.Init` 必然成功
- 8 台设备 = 8 条独立的 2ch 输出链路，彼此不共享任何 WASAPI 对象

代价是每台设备都要一条 `WasapiOut`（8 条线程 + 8 个 COM 音频客户端），CPU 与句柄开销按路线性增长。8 路 × 48k × 2ch 的混音 + 插值约占总 CPU 的 3~5%，可接受。

#### 2.3.2 声源侧：`srcCh` 不能写死

系统只有 2 声道端点时，loopback 也只能拿到 2 声道，拼不出 6 声道。两条路：

| 声源 | 做法 | 保真度 |
|---|---|---|
| 真 5.1（电影 / 游戏） | 把 **VB-CABLE 在 Windows 里配成 5.1** 并设为默认输出 → loopback 捕获到 6ch/48k → 3 台设备各取一对 | 原样透传，最高 |
| 只有立体声 | 软件内矩阵上混 2ch→6ch（`upmix-5.1` 预设）再分发 | 中置/环绕为合成，LFE 为伪低通 |

关键：两种情况下**引擎看到的东西一样**——一个 `srcCh` 声道、`sampleRate` 采样的交错流。上混只是"把源虚拟成 6 声道"，下游路由代码不分叉。所以 `SinkRouter` 的签名固定为：

```csharp
void Process(float[] src, int srcCh, int offset, int frames, float[] dst);
```

`srcCh` 由捕获格式（= 默认输出端点的 mix format）决定，不写死 2。现有代码里所有 `/4`、`* 4`、`blockAlign` 相关的 2 声道假设都在 P1 一并泛化。

#### 2.3.3 对齐由每路自己的时钟环维持 —— 所以**每路必须独立一组**

这是最反直觉、也最容易做错的一点。

单台设备内部：一个 `DriftCorrectingProvider` 的 `ratio` 对整块交错数据统一施加（`Read` 里对所有采样用同一个 `ratio`），所以**同一台设备的 2 个声道相位天然一致**，不存在偏音。

跨设备：各设备晶振独立，若共用一个 `ratio`，就只有平均水位被拉回目标，个体水位会缓慢发散 —— 而水位就是延迟：

```
latency_i = target_i + outMs_i + physical_i
target_i  = fillTargetSamples + delay_i × sampleRate
```

水位漂移 50ppm，一小时就是 180ms，设备间对齐彻底崩掉（声像跳、梳状滤波）。

反过来，**每路独立一组**时，每路的 ratio 把自己的水位锁在 `target_i`，`latency_i` 恒定不变，标定一次就一直有效。而且 intra-pair 相位由"同一个 provider 同一个 ratio"保证，偏音问题根本不会出现——因为拼装拓扑里相关声对（FL/FR、SL/SR）本来就落在同一台设备上。

结论：

| 场景 | 时钟组配置 | 理由 |
|---|---|---|
| 旧版双设备 `mono-left` / `mono-right`（L 和 R 分居两台设备） | 两路同组 `g0`（**保持现状，默认值**） | 相关声对跨设备，必须共用 ratio 才能消偏音 |
| 拼装 5.1/7.1（每台设备各持一对） | **每路独立组**（`ClockGroup` = 空） | 相关声对不跨设备；独立组才能锁住设备间对齐 |

所以 `ClockGroup` 的默认值不能统一：`Map` 是 `mono-left`/`mono-right` 时自动同组，其余预设一律独立组。用户可手动覆盖，UI 上组名留空即"独立"。

#### 2.3.4 一次性标定无法省掉

软件测不到 USB/DAC/蓝牙/音箱的物理延迟（§6.3 的 WASAPI 接口不暴露）。拼装拓扑下这直接决定"左前置的声音比右前置早 40ms 到耳朵"，必须人工标定一次：

- 提供**逐路测试音**：把一段 1kHz 短促脉冲（约 30ms，带 5ms 淡入淡出）单独发到指定一路，其余路静音
- 用户以"最早到耳朵的那一路"为基准，给其余各路填 `DelayMs`，直到听感重合
- 标定值与设备绑定存在 ini 里，换设备才需重做

详细流程见 §7.1。

## 3. 目标数据流

```
WasapiLoopbackCapture(默认输出, srcFmt)
  │  DataAvailable(buf, len)
  ├─► SinkRuntime[0].Consume(buf, len)
  │      SinkRouter(map0) → 交错 float[frames × ch0]
  │      → DelayLine(delay0) → Buf0(outFmt0)
  │      → DriftCorrectingProvider(ch0, groupA) → WasapiOut(dev0, outFmt0)
  ├─► SinkRuntime[1].Consume(buf, len)
  │      SinkRouter(map1) → ... → WasapiOut(dev1, mixFmt1)
  └─► SinkRuntime[n] ...（禁用路不在列表里，零开销）

捕获线程：一次读取，N 次混音（push 模型，与现有一致）
输出线程：每路一条 WASAPI 线程，各自拉自己的 Buf（pull 模型，与现有一致）
```

关键点：**混音必须在每路各自的延迟线之前**，因为每路 `DelayMs` 不同。混音结果按路缓存在复用数组里，不进堆分配（沿用现有 `splitOut/splitF` 的复用思路）。

图中的 `SinkRouter(mapN)` 里的 `mapN` 就是 `RoutingModel.Compile()` 折叠出来的 `SinkMatrix[N]`（§5.8）——编辑期的"逻辑声道 → 绑定"三层结构不进运行时，运行时只看到一层矩阵。

## 4. 配置项设计

### 4.1 ini schema

沿用 `SplitterGUI.ini`（`SettingsStore`，键值 + 插入顺序 + 原子写）。存的是**编辑期三层模型**：逻辑声道（`Chan*`）、绑定（`Bind*`）、设备（`Sink*`）。

为什么存三层而不是存编译后的矩阵：矩阵是派生数据，存了就丢掉"为什么这么混"（哪个声道是 L+R 合成的中置），UI 没法反解、手改也无从下手。三层读回来再 `Compile()` 一次，成本可忽略。

| 组 | 键 | 说明 |
|---|---|---|
| 模式 | `RoutingMode` | `split-lr` / `mirror-stereo` / `surround` / `mono-broadcast` / `custom` |
| | `RoutingLayout` | `mono` / `stereo` / `quad` / `5.1` / `7.1` / `custom` |
| 逻辑声道 | `ChanCount` | 声道条数（≤16） |
| | `Chan{i}.Key` `Name` `Kind` `Gain` `Mute` | `Kind` ∈ `FL/FR/C/LFE/SL/SR/BL/BR/G` |
| | `Chan{i}.TapCount` / `Chan{i}.Tap{t}` | 抽头表，`src*gain`，如 `2=0*0.5+1*0.5` 写成两条 `Tap` |
| 绑定 | `BindCount` | ≤64 |
| | `Bind{j}` | `通道Key,设备Key,物理声道,增益`，如 `ch2,s1,0,1` |
| 设备 | `SinkCount` | 路数（≤8，含停用路；删除后不重排索引，避免下游错位） |
| | `Sink{n}.Key` `Label` `DeviceId` `Name` | `Name` 是友好名缓存，ID 失配时按它二级匹配（§5.7） |
| | `Sink{n}.Enabled` `DelayMs` `ClockGroup` `Channels` | `ClockGroup` 空 = 独立校正组；`Channels` 是保存时的物理声道数 |

其余沿用现有键（`LatencyProfile`、`Gain`、`VolumeMaster`、`MuteCapture`、`DriftMode`、`FixedRatioPpm`、`WaterIntervalSec`、`MinimizeToTray`、`DeviceDefault`）。`DeviceLeft`/`DeviceRight` 继续同步写入（旧版可回退），读取时作为 `Sink0/Sink1` 的兜底来源。

### 4.2 Tap / Bind 语法

```
Chan{i}.Tap{t} := srcIdx "*" gain
                 缺省或 ""  → 该声道没有这个抽头（抽头全空 = 该声道静音）
Bind{j}        := 通道Key "," 设备Key "," 物理声道 [ "," 增益 ]
```

- `srcIdx` 越界（源只有 2ch 却写 `2*1.0`）→ 编译时按 `srcIdx % srcCh` 折叠并记一条日志（保留旧版"单声道捕获时取模回 ch0"的行为）
- `gain` 容许 0.0~2.0；同一物理声道被多条绑定命中会**相加**，靠 provider 的硬限幅兜底，模板本身留了余量
- 抽头为空 = 静音（用于 LFE 没有独立低音的场景）
- 脏数据（字段不足、非数字）整条丢弃，不猜：宁可少一条绑定，也不要悄悄接到错的声道上

### 4.3 模板系数

工作模式与布局决定初始清单，系数取工程常用近似（非 Dolby/DTS 授权系数），目标是"声场合理、不削波"。中置用 0.5 而非 0.707，正是为了 `L+R` 求和后不削波。

| 模式 / 布局 | 逻辑声道（抽头） |
|---|---|
| `split-lr` | 左 `0*1.0`、右 `1*1.0`；两个声道各绑一台设备的 p0 |
| `mirror-stereo` | 左 `0*1.0`、右 `1*1.0`，各绑到**全部**启用设备的 p0/p1 |
| `surround` + 5.1 | `FL=0*1`、`FR=1*1`、`C=0*0.5+1*0.5`、`LFE=0*0.35+1*0.35`、`SL=0*0.7`、`SR=1*0.7` |
| `surround` + 7.1 | 上述 6 个 + `BL=0*0.7`、`BR=1*0.7` |
| `surround` + quad | `FL=0*1`、`FR=1*1`、`BL=0*0.7`、`BR=1*0.7` |
| `mono-broadcast` | 单声道 `0*0.5+1*0.5`，绑到每台设备的每个物理声道 |
| `custom` | 不改清单，只用当前 ini 里已有的 |

下混（6ch 源 → 2ch 设备）不在模板里硬编码：等 P4 拿到真实多声道捕获后按 `srcCh` 选择抽头表，此前 `srcIdx % srcCh` 的折叠已经保证 2ch 源不会炸。

### 4.4 迁移与校验

- **旧配置**（无 `SinkCount`）：`DeviceLeft`/`DeviceRight` → `Sink0/Sink1`（`split-lr`，各自 `Channels=1`、`DelayLeft/Right` 继承、`ClockGroup=g0`、`Enabled=1`）。行为与旧版**逐字节等价**（同一 Split 语义、同一 ratio 共享）。首次加载后立刻写出新 schema（`pendingSchemaRewrite` → `FlushSettings`）
- **新写旧读**：`DeviceLeft`/`DeviceRight` 始终同步为 `Sink0/Sink1` 的 DeviceId，旧版仍可启动；新键被旧版忽略
- **删键回退**：把所有新键删掉，仍能靠 `DeviceLeft/DeviceRight` 启动并重新写出新 schema（P2 验收标准）
- **端点 ID 失配**：ID → 全名 → 归一化名（去 `2- ` 序号、`默认设备` 后缀）三级回落，命中后把新 ID 写回 ini；都落空才保持"未绑定"并记日志
- **启动前校验**（`ValidateSinks` / `Validate`，Error 挡启动并弹一句人话，Warn/Info 只进日志）：
  1. 至少 1 路 `Enabled`
  2. 启用路之间 DeviceId 不得重复（同一端点开两个 `WasapiOut` 会互相抢占，实测表现为其中一路静音）
  3. 任一路 DeviceId 不得等于捕获设备（回环）
  4. 每路 `Channels` **大于**端点实际声道数时收窄到实际值并记 Warn（`ArgumentException: 尚未实现` 的来源）；**小于**端点时保持原值不改——`Channels` 是"这一路用几个物理声道"，左右分离就是拿 2ch 音箱的 1 个声道，改成 2ch 会让未绑定的 p1 静音，听感少一半
  5. 绑定指向停用路 = Info（配置保留），指向不存在的路 = Warn

### 4.5 工作模式与声道清单

工作模式决定"默认要几个逻辑声道、怎么分配"，之后所有细调都落在**声道清单**与**绑定表**上。模式本身不参与运行时——它只是**生成/改写**清单的一次性动作。

| 模式 | 逻辑声道默认 | 默认绑定 | 用途 |
|---|---|---|---|
| `split-lr` 左右分离 | 2（左/右） | 每声道各绑 1 台，`Channels=1` | 现行为：两只单声道设备分放左右 |
| `mirror-stereo` 同源并播 | 2（L/R） | 每声道绑**全部**启用设备，`Channels=2` | 多房间同播、两副耳机听同一内容 |
| `surround` 拼装环绕 | 6（5.1）/ 8（7.1） | 按设备顺序两两一组 | N 台 2 声道设备拼 N×2（§2.3） |
| `mono-broadcast` 单声广播 | 1（L+R 混音） | 绑全部设备的全部物理声道 | 全屋放同一个人声/背景音乐 |
| `custom` 自定义 | 保留当前清单 | 不动 | 手搭 |

新增键（与 `Sink{n}.*` 平级）：

| 键 | 类型 | 范围 | 默认 | 说明 |
|---|---|---|---|---|
| `Mode` | enum | 上表 5 值 | `split-lr` | 工作模式 |
| `ChannelLayout` | enum | `mono`/`stereo`/`quad`/`5.1`/`7.1`/`custom` | `stereo` | 命名与标准声道序（只影响显示与编号） |
| `ChannelCount` | int | 1~16 | 2 | 逻辑声道数，用户手动加减的结果 |
| `Ch{n}.Key` | string | `ch0`~`ch15` | 自动 | 稳定标识，绑定表引用它 |
| `Ch{n}.Name` | string | ≤6 字 | 按布局 | 显示名（左前置/中置/低音…） |
| `Ch{n}.Kind` | enum | FL/FR/C/LFE/SL/SR/BL/BR/Generic | 按布局 | 只影响图标与配色，不影响声音 |
| `Ch{n}.Taps` | string | `0*1.0,1*0.5` \| `mute` | 按布局 | 源声道抽头，语法同 §4.2 |
| `Ch{n}.Gain` | int | 0~200 | 100 | 总线增益（%），一次影响所有绑定它的设备 |
| `Ch{n}.Mute` | 0/1 | | 0 | 静音（保留绑定，不删配置） |
| `BindCount` | int | 0~64 | 自动 | 绑定条数 |
| `Bind{i}.Channel` | string | `Ch{n}.Key` | — | 逻辑声道 |
| `Bind{i}.Sink` | string | `Sink{n}.Key` | — | 目标设备 |
| `Bind{i}.Phys` | int | 0 ~ 该路 `Channels`-1 | 0 | 该设备的第几个物理声道 |
| `Bind{i}.Gain` | int | 0~200 | 100 | 这条绑定的增益（%），**并联降功率用** |

`Sink{n}.Channels` 语义收紧为"**该路实际使用几个物理声道**"（1 ~ 端点声道数），不再只是回读值。`mono-left/right` 用 1，拼装场景用 2。

示例（3 台 2 声道设备拼 5.1，取前几条）：

```ini

ChannelLayout=5.1
ChannelCount=6
Ch0.Key=ch0
Ch0.Name=左前置
Ch0.Kind=FL
Ch0.Taps=0*1.0
Ch2.Key=ch2
Ch2.Name=中置
Ch2.Kind=C
Ch2.Taps=0*0.5,1*0.5
```

**上混/下混不需要单独机制**：它就在 `Ch{n}.Taps` 里。2ch 源要出中置，写 `0*0.5,1*0.5`；5.1 源要出立体声，写 `0*1.0,2*0.7`。§4.3 的预设从此只是"初始 Taps 的模板"，不再是运行时的特殊分支。

**迁移**：ini 无 `Mode` 时，按旧 `Preset/Map{j}` 在内存里反向合成等效清单（`mono-left` → 1 个逻辑声道 `ch0=Taps:0*1.0` 绑 `s0.Phys0`），首次保存时写成新 schema。反向写回旧键只在"模式仍是 `split-lr` 且绑定未编辑"时做；其余情况放弃旧版回退（矩阵无法用 8 条 `Map{j}` 无损表达）。

#### 5.3.1 provider 必须改成按帧处理（否则左右串音）

现有 `DriftCorrectingProvider` 是**单声道**的：64 样本小环 + 一个 `phase`，`Read` 里每输出一个样本就 `phase += ratio`。这个结构只能喂 1ch（现在正是如此，每路输出格式是 `CreateIeeeFloatWaveFormat(rate, 1)`）。拼装拓扑下每台设备要出 2ch 交错数据，直接复用会坏掉：

- 交错流是 `L,R,L,R…`。`phase` 落在两个样本之间时，Catmull-Rom 会在 **L 与 R 之间**插值 → 左右互相漏音 + 互调失真
- `ratio ≠ 1` 时 `phase` 会遍历所有小数值，串音持续存在，听感是"声场塌陷、人声发闷、低频散"
- 水位口径也跟着错：`src.BufferedBytes / 4` 在代码里被当成"样本数"，2ch 交错时它实际是"2 倍样本数"→ 校正环把水位拉到目标的一半，实际延迟凭空减半

所以 P1 必须做三件事：

1. `channels` 进构造函数；小环扩成 `channels × RingSize`，`prev` / `ring` 按通道分开存
2. `phase` 每**帧**推进一次（`ratio` 的作用对象是帧，不是样本），同一帧内所有通道用同一个 `phase` 插值
3. 所有水位换算改成帧口径：`frames = BufferedBytes / (4 * channels)`，`Fill()` 的 `want`、`StepStarved()` 的 `total`、`BufferedMs` 一并改

```csharp
public DriftCorrectingProvider(BufferedWaveProvider src, int targetSamples, int channels, ...)

// Read 内, 帧优先:
for (int f = 0; f < frames; f++)
{
    for (int ch = 0; ch < channels; ch++)
        samples[(f * channels) + ch] = Cubic(prev[ch], ring[i1, ch], ring[i2, ch], ring[i3, ch], phase) * gm;
    phase += ratio;
    while (phase >= 1.0) { /* 整帧搬移: 所有通道一起前移 */ }
}
```

顺带得到一个结构性好处：同一帧的所有通道共用 `phase`，**跨通道相位天然一致**，与"每路一个 provider"配合，§2.3.3 要的"相关声对同设备、绝对相位一致"在代码结构上就被保证了，不依赖参数调得好。

### 5.8 逻辑声道模型（编辑期）与编译（运行期）

```csharp

    public enum Sev { Error, Warn, Info }
    public Sev Severity; public string Where; public string Message;

```

**三层折叠成一层（这套设计的核心）**：`Taps`（源 → 逻辑声道）与 `Bindings`（逻辑声道 → 物理声道）在 `Compile()` 里乘起来，得到与旧 `Sink{n}.Map{j}` **完全同形**的矩阵：

```
matrix[sink][phys][src] = Σ bind.Gain × Σ tap.Gain
                          bind∈(sink,phys)  tap∈tap.Src==src
```

于是运行时 `Consume` 只读 `SinkMatrix`，**逻辑层不参与逐样本运算，零额外开销**；`DelayLine` / `BufferedWaveProvider` / `DriftCorrectingProvider` 一个字符都不用改。一句话概括：**逻辑层是编辑期模型，矩阵是运行期模型**。

**多设备共用同一声道**因此天然成立：同一个逻辑声道挂多条 `Bind`（不同 `Sink`/`Phys`），折叠后各自矩阵里都有这一路的抽头。不需要"共享缓冲"或"分叉输出"之类的特殊机制——每路本来就是独立缓冲、独立延迟、独立校正，并联只在矩阵里体现。

**热更新**：`CompiledRouting` 是不可变对象，引擎持一个 `volatile` 引用，`Consume` 每次取本地副本。运行中改绑定/增益/静音 = `Compile()` 出新对象并原子替换，**不停链路、不断音**。换设备（`DeviceId`）仍需停链路（COM 竞态），与 §8 约束一致。

**校验规则**（`RoutingIssue` 直接驱动 UI，不重复判断）：

| 级别 | 条件 | UI 表现 |
|---|---|---|
| Error | `Taps` 引用 `Src >= srcCh` | 卡片红框 + 状态行，禁止启动 |
| Error | `Bind.Phys >= Sink.Channels` | 绑定行红字，禁止启动 |
| Error | 全部 sink 禁用 / 无绑定 | 开始按钮禁用并说明 |
| Warn | 逻辑声道未绑定 | 卡片灰边"未分配"，允许启动（该声道静音） |
| Warn | 同一 `(sink, phys)` 被 >1 逻辑声道绑定 | 绑定行黄标"求和"，提示可能削波 |
| Warn | 同一逻辑声道绑到 >1 设备 | 提示同空间并联会有梳状滤波（§11） |
| Info | 绑定的 sink 已禁用或未插 | 卡片角标"离线"，配置保留 |

## 6. 与现有逻辑的兼容方式

逐条对照，每条都给出"不改会怎样"，避免实现时漏项。

| 现有逻辑 | 兼容做法 | 不改的后果 |
|---|---|---|
| **偏音修复**（shared ratio） | `ClockGroup` 成员集合；`mono-left/right` 预设下前两路默认同组，其余预设默认独立组（§2.3.3）。`MemberCount=2` 时公式与现实现逐值相同 | 每路独立 ratio 会让跨设备的左右插值方向不对称，偏音回归；但拼装拓扑里相关声对同设备，不存在这个问题 |
| **holding 联动**（-6dB） | `AnyOtherHolding(key)` 只在组内、且组内成员 >1 时生效；单路组恒为 false | 独立组下恒为 false，正是想要的：拼装时设备 A 欠载不应把设备 B 也降 6dB |
| **`Sink{n}.Preset` / `Map{j}`** | 保留读取与反解；新写 `Mode` / `Ch{n}.*` / `Bind{i}.*`。只有 `Mode=split-lr` 且绑定未被编辑时才回写旧键 | 旧版回退只在最简单的场景成立，其余放弃（矩阵无法用 8 条 `Map{j}` 无损表达） |
| **设备行上的"映射"入口** | 删除，路由统一在声道卡片上编辑；设备行只留"用几个物理声道" | 两个入口编同一份数据，必然出现不同步 |
| **`Split()` 单声道抽取** | 由 `mono-left/right` 预设表达，`channel % ch` 折叠逻辑移进 `FitSource` | 源为单声道时越界读 → 进程被杀（现有注释已记录这个坑） |
| **`DriftCorrectingProvider` 声道数** | 加 `channels` 参数, `phase` 按帧推进, 小环按通道分开, 水位换算改帧口径（§5.3.1） | 交错流按样本插值会在 L 与 R 之间过渡 → 左右串音; `BufferedBytes/4` 在 2ch 时把水位算成 2 倍 → 延迟减半 |
| **`DelayLine`** | 每路一条，混音后按该路 `DelayMs` 建；`BytesOf(wf, ms, blockAlign)` 用该路输出格式 | 用捕获格式算字节数会让 6ch 输出的延迟只有 1/6 |
| **预缓冲**（`fillBytes` 等待） | 遍历启用路，各自 `fillBytes = fillTargetSamples * outCh * 4`；超时上限取 `max(各路 fillMs + delayMs) + 1000` | 只等两路会让慢设备（蓝牙）起播即欠载 |
| **修剪**（`TrimTo`） | 逐路 `TrimToFill()`，统一修剪到各自 fillBytes | 快路多攒的水位抵消延迟线时差，延迟补偿失准 |
| **输出缓冲溢出告警** | 告警带 `Label`，60 秒/路限流 | 多路共用一条限流会吞掉真正出问题那一路 |
| **看门狗停摆** | 逐路 `RenderedSamples`，冻结 10 秒 → 只重建该路（`SetSinkEnabled` 循环） | 一路休眠导致整体重启，正在播的其他路被硬切 |
| **看门狗失衡** | 判据从"左/右 vs 组内平均"推广为"某路调节水位 > 300ms 且组 ratio 触顶 > 10 秒" | 5.1 设备里只有一路失配时检不出来 |
| **`WasapiOut` 生命周期** | 每路独立 `PlaybackStopped` → `SinkFailed(key, why)`；`stopping` 标志仍屏蔽主动停止 | 单路停止会被当成整机故障 |
| **端点音量双向绑定** | `VolumeBindingSet` 按 key 管理；UI 每行滑条绑自己的 key | `Master/Left/Right` 固定槽位无法表达第 3 路 |
| **UI 值权威写回** | `WriteValues` 遍历启用路 | 新增路启动时音量取端点旧值，与 UI 不一致 |
| **`RestoreDefaultOutput`** | 不变（捕获端仍是单路） | 停止后系统默认卡在虚拟声卡 → 全部无声 |
| **自动重建**（`MaxAutoRestart`） | 捕获端故障 → 全链路重建；单路故障 → 只重建该路，不消耗整体重试额度 | 一路坏掉把整体重试次数耗光，最后 `GiveUp` |
| **单实例 / 托盘 / 前台激活** | 不变 | — |
| **`Program` 内嵌 NAudio 解析** | 不变（未新增程序集依赖） | — |

### 6.1 采样率不一致（实测已可免费解决）

`WasapiOut` 在共享模式下给了 NAudio 一个"自动转换"路径：实测把 44.1k / 96k / 16bit provider 交给 48k 端点，`Init` 全部成功（`IsFormatSupported` 却报 no）。说明 NAudio 在 `Initialize` 时带了 `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY`，由 Windows 音频引擎做采样率与位深转换。

因此 v1 的取向是**不自己重采样**：`provider.WaveFormat` 的采样率直接用捕获源采样率，采样率差交给系统 SRC。好处是零新增代码、零新增缓冲；代价是系统 SRC 的延迟（几毫秒）与音质不可控，且与漂移校正叠加时无法精确建模。

若后续要精确（v2，可选）：`DriftCorrectingProvider` 增加 `baseRatio = (double)srcRate / dstRate`，`phase += baseRatio * ratio`，让校正环直接工作在端点采样率上。

- `baseRatio` 偏离 1 在 ±10% 内时 Catmull-Rom 的混叠落在 21kHz 以上，可接受（48k↔44.1k 为 0.919/1.088）
- 偏离超过 10%（96k → 44.1k）才改用 `WdlResamplingSampleProvider` 前置转换
- 水位换算：`BufferedBytes / (4 * outCh)` 得帧，除以采样率得毫秒 —— 与延迟线的毫秒口径天然一致，**不受是否走系统 SRC 影响**（时间轴相同）

### 6.2 上混的削波

矩阵求和 `Σ gain` 可能 >1。三层防护：预设系数留余量（最大和 1.4，但只在极端同相信号下触顶）→ provider 现有 `if (v > 1f) v = 1f` 硬限幅 → 日志在单路连续限幅时记一条（新增计数器，限流 60 秒）。

### 6.3 格式协商实测（本机 8 个活动端点，2026-11-15）

本机全部端点的 mix format 均为 `48000Hz / Extensible / 32bit / 2ch / sub=IEEE_FLOAT`，因此 5.1/7.1 三条路径**无法在本机验证**，P4 需要在有 5.1 端点的机器上复测。

| provider 格式 | IsFormatSupported(Shared) | WasapiOut.Init | 结论 |
|---|---|---|---|
| f32 1ch @48k（少于端点声道） | no | **ok** | 系统自动上混到 2ch |
| f32 2ch @48k（= mix format） | yes | **ok** | 原生路径 |
| f32 2ch @44.1k / @96k | no | **ok** | 系统 SRC 转换 |
| pcm16 2ch @48k | yes | **ok** | 位深转换可用 |
| f32 6ch @48k（多于端点声道） | no | **ArgumentException: 尚未实现** | 客户端声道数不得大于端点声道数 |
| f32 8ch @48k | no | 同上 | 同上 |

三条落地结论：

1. **`OutChannels = min(端点 mix 声道数, 目标布局声道数)`**，启动前校验，超了就拒绝并提示"该设备端点为 2.0，请先在 Windows 里配置为 5.1/7.1"
2. 报错文案必须自己翻译：`ArgumentException: 尚未实现` 对用户毫无意义，映射成"设备声道配置不匹配"
3. 因为 `IsFormatSupported` 会给出误导性的 `no`，**不要用它做启动门槛**，直接 `Init` + 捕获异常更准

## 7. 设备变化时保持配置有效

三层保障，缺一层就会丢配置：

1. **存储层**：配置按 `DeviceId`（endpoint ID，Windows 分配后稳定）+ `CachedName` 双写。ID 变化时名称兜底，名称变化时 ID 兜底，两者都变才需要人工重选
2. **解析层**：`SinkResolver` 每次启动/刷新都重新解析，匹配成功即把新 ID 回写 `SinkConfig`（并记日志"设备 ID 已更新"），配置条目永不因失配被删除
3. **事件层**：`DefaultChangeWatcher` 增加 `OnDeviceAdded(deviceId)` 回调 → 若有 `NotFound` 的路其名称与新增设备匹配，自动补建该路

运行时行为矩阵：

| 事件 | 现有行为 | 新行为 |
|---|---|---|
| 某路设备被拔 | 整体 `OnEngineStalled` → 全量重建 | 该路 `SinkFailed` → 只停该路，标 `Healthy=false`，其余继续；配置保留 |
| 某路设备插回 | 不自动恢复（需手动开始） | `OnDeviceAdded` 匹配成功 → 自动补建该路，填满预缓冲后渐入 |
| 捕获设备（系统默认）变化 | 全链路重建 | 不变（捕获格式可能变，必须整体重建） |
| 用户刷新设备 | 重建下拉，按 ini 恢复选中 | 重建列表，逐路重新解析，标红不存在的路 |
| 用户换 USB 口（ID 变） | 找不到 → 静默回退到索引 0 | 名称匹配成功 → 自动绑定，日志说明 |

### 7.1 拼装拓扑的延迟标定（§2.3.4 的可执行流程）

跨设备的物理延迟软件测不到，必须在装配时标定一次。标定值随设备存在 ini 里，之后不再需要干预。

**试听音设计**：1kHz 正弦 + 汉宁窗，时长 30ms，间隔 1s 重复 6 次。不用咔哒声（宽频，人耳判重合不准），也不用长音（相位模糊）。播单路时其余路强制静音，避免串音干扰判断。

**流程**：

1. 全部启用，`DelayMs` 先全填 0
2. 点某路的「试听」，确认这台设备确实出声、左右位置正确（验证映射没接错）
3. 选一台**有线**设备作基准（物理延迟最小且最稳定），其余路相对它补延迟
4. 进「对齐」模式：基准路 + 当前路同时播同一串脉冲。调当前路的 `DelayMs`，直到两串脉冲**重合为一个**（判据是响度变大、瞬态变实，不是音色）
5. 步进：>20ms 用 10ms 步，10~20ms 用 5ms 步，<10ms 用 1ms 步。人耳对 5ms 以上可辨，1~3ms 的残差在环绕声道上听不出来
6. 蓝牙路先粗调到 150ms 再细调（典型 100~300ms）；蓝牙的**抖动**补不了，只能取平均值，信号差时仍会飘
7. 全部填完，`DelayMs` 写入 `Sink{n}.DelayMs`

**为什么标定一次就够**：每路的 ratio 把水位锁在 `target_i = fill + delay_i`（§2.3.3），`latency_i` 恒定，所以设备间对齐不会随时间漂移。换 USB 口、拔插、重启都不需要重标定——重建后水位仍回到同一个 `target_i`。只有**换了物理设备或链路**（换音箱、蓝牙改有线、插到另一台机器）才需要重做。

**运行中改 `DelayMs` 的代价**：延迟线按新长度重建，该路会瞬断约 10~20ms。用现有 `fadeIn` 机制 3ms 淡出淡入掩盖即可；但标定本身建议在停止状态下做，边听边调更准。

## 8. 运行时启用 / 禁用

- **禁用**：`sink.Enabled=false` → `Stop()` + `Dispose()` 该路（释放 `WasapiOut`、`MMDevice`、`DelayLine`、`BufferedWaveProvider`），从 `sinks` 列表移除。资源占用归零，看门狗不再看它
- **启用**：新建该路 → 填到 `fillBytes` → `Play()`。为避免"从 0 水位起播"的咔哒，采用 3ms 淡入（provider 已有 `fadeIn` 机制，起播时置 0 即可复用）
- **不影响其他路**：`ClockGroup` 成员数变化会改变 `SwitchAfterUpdates` 归一系数，但 `ratio` 与 `kpNow` 连续保持，不重置（否则组内水位会突跳）
- **UI 约束**：运行中允许改 `Enabled`、`Volume`、`Mute`、`DelayMs`（重建该路延迟线）、`Map`（重算路由）；**不允许**改 DeviceId（需停止后改，避免端点切换时的 COM 竞态）

- 设备区用 `FlowLayoutPanel { FlowDirection = TopDown, WrapContents = false, AutoScroll = true }`，行数超出即出现竖向滚动条；**不要**让窗口高度跟着行数涨（行数无上限，窗口会超出屏幕）
- **滚动条出现后行宽要重算**：竖滚动条会吃掉 17px `ClientSize.Width`，行宽固定不变就会被右边缘裁掉。订阅 `ClientSizeChanged` 把每行 `Width` 设为 `ClientSize.Width - 4`（有滚动条时同样适用），并让行内右侧的 `[×]` 按钮 `Anchor = Right`
- **滚轮要被列表接管**：`TrackBar` / `NumericUpDown` / `ComboBox` 会吞掉 `WM_MOUSEWHEEL`，光标停在音量条上滚动就会改音量（现版本已用 `NoWheelComboBox` 单独堵了 ComboBox，多路列表下这个问题会变成"滚列表顺手改了延迟"）。改为在 `Application` 层装一个 `IMessageFilter`：光标落在设备区内且控件不是可滚动容器时，把滚轮消息转给 `FlowLayoutPanel` 并返回 `true`。这样一处统一处理，行内所有控件都不再需要 `NoWheel*` 变体
- **增删行保持滚动位置**：新增行后 `ScrollControlIntoView(newRow)`；删除行不动 `AutoScrollPosition`。`Tab` 顺序按行号重建，否则焦点会跳到已删除的控件上
- 小屏兜底：`OnLoad` 里 `Height = Math.Min(720, Screen.WorkingArea.Height - 80)`，按上表优先级压缩（日志 → 设备区 → 声道清单），保证至少 2 行设备可见
- 设备行不再有"映射"按钮：声道路由全部在声道卡片上编辑（§9.2），设备行只保留"用几个物理声道"（`1ch` / `2ch`）与「试听」。原模态 `ChannelMapDialog` 取消——它是设备视角，会与新的声道视角互相打架
- 状态行分两段：左段固定 `模式 拼装环绕 | 声道 6/6 | 设备 3 台运行中`，右段逐路紧排 `s0 96 s1 98 s2 101`（空间不足时只显示触顶/欠载的路，其余折叠成 `其余正常`）

### 9.1 工作模式选择器

放在窗口最顶部一条**模式带**（不是下拉框）：5 张等宽卡片，每张一个 8×8 示意图 + 名称，点选即生效。下拉框只能看到当前值，卡片带能让人一眼看到"有哪些可能"，且当前模式自己亮着。

```
模式  ┌─────────┬─────────┬─────────┬─────────┬────────┐
      │  ▮  ▮   │ ▮▮ ▮▮   │▮▮ ▮▮ ▮▮ │  ▮  ▮   │   ⚙    │
      │ 左右分离 │ 同源并播 │ 拼装环绕 │ 单声广播 │ 自定义 │
      └─────────┴─────────┴─────────┴─────────┴────────┘
      ● 3 台设备 → 6 声道（5.1）· 每台出 2 声道 · 全部已绑定
```

- 模式带下方那行摘要随选择**立刻**变（"会发生什么"先于操作可见）
- 清单为空时选模式 → 直接生成默认清单与绑定；清单非空 → 模式带下方出现一条内联确认条 `切换会重排声道清单与绑定，手改将丢失 [切换] [取消]`，**不弹模态框**（否则会打断试听）
- `custom` 不动清单，只把模式标记为"用户接管"，之后改任何东西都不再回退模式
- 设备不足时（例如选"拼装环绕"但只有 1 台），该卡片仍可点，但摘要行给出 `需要 ≥3 台设备，当前 1 台`，并自动只生成 2 个声道

### 9.2 声道清单（可视化）

设备区上方一条**横向可滚动卡片带**，每张卡 = 一个逻辑声道：

```
声道  [6 ▼] 布局[5.1 ▼] [+ 加一个] [自动绑定]        已分配 6/6
┌──────────┐┌──────────┐┌──────────┐┌──────────┐┌──────────┐┌──────────┐
│●左前置 FL││●右前置 FR││●中置  C  ││●低音 LFE ││●左环绕 SL││●右环绕 SR│
│ L×1.0    ││ R×1.0    ││ L+R ×.5  ││ L+R ×.35 ││ L×.7     ││ R×.7     │
│ → 左设备0 ││ → 左设备1 ││ → 中置0   ││ → 中置1   ││ → 右设备0 ││ → 右设备1 │
└──────────┘└──────────┘└──────────┘└──────────┘└──────────┘└──────────┘
   ● 绿=已绑定   ○ 灰=未分配   ● 红=冲突   ● 黄=离线
```

卡片固定三行信息，**任何改动都落在这三行里**，不用点开就知道状态：

| 行 | 内容 | 示例 |
|---|---|---|
| 1 | 状态点 + 名称 + Kind 缩写 | `●左前置 FL` |
| 2 | 源抽头（超 2 项截断成 `L+R+2…`） | `L+R ×.5` |
| 3 | 承接设备 + 物理声道（多台时显示 `→ 3 台`，悬停列出） | `→ 左设备0` |

- 点卡片 → 非模态浮层改 `Taps / Gain / Mute / 绑定`（可边听边调，不用关窗口）
- 卡片右上角 `×` 删声道（连带删它的绑定）；`+ 加一个` 追加 `custom` 声道（默认 `Taps=0*1.0`、未绑定）
- `声道 [N ▼]` 是"要几个声道"的入口，选 N 后按 `ChannelLayout` 补齐标准声道名；从大改小时多出的声道与绑定被删，弹内联确认条
- 拖卡片排序 = 逻辑声道序（影响日志前缀与环绕编号），拖拽时其余卡片让位
- 卡片最小宽 108；`ChannelCount × 116 > 可视宽` 时卡片带横向滚动（滚轮同理走 §9 的 `IMessageFilter`）

**实时反映**（三处联动，改任一处另外两处立即跟上）：

| 操作 | 立即刷新的位置 |
|---|---|
| 改声道数 | 卡片带增删、`已分配 x/y`、设备行 `承担 N 声道`、状态行 |
| 改源抽头/增益 | 该卡片第 2 行、状态行峰值估算 |
| 改绑定 | 该卡片第 3 行、设备行、冲突角标、开始按钮可用性 |
| 拖排序 | 卡片顺序、日志前缀 `[ch2 中置]` |

刷新实现：任何改动 → `Validate + Compile` → 一次 `BeginUpdate/EndUpdate` 批量重画；连续输入（拖数字框）按 30ms 合并，不逐次重建控件。运行中改绑定走 §5.8 的原子替换，**不断音**。

### 9.3 状态可见性

从粗到细三层，保证"任何时候都知道现在是什么状态、为什么不能启动"：

1. **模式摘要行**（模式带下方）：`3 台设备 → 6 声道（5.1）· 每台 2 声道 · 全部已绑定`
2. **卡片状态点 + 设备行徽标**：绿/灰/红/黄；设备行尾显示 `承担 2 声道`，离线设备打 `离线` 徽标
3. **底部状态行**：`模式 拼装环绕 | 声道 6/6 | 设备 3 台运行中 | 水位 96 98 101 | 无告警`

启动前置：`Validate` 出 Error 时「开始分流」置灰，按钮左侧显示**第一条** Error 的人话（`⚠ 中置引用了不存在的源声道 2`），点按钮展开全部问题；只有 Warn 时按钮可用，旁边挂 `警告 2` 徽标可点开。

空状态：没有设备时卡片带显示 `先添加输出设备 → 再选工作模式`，模式卡片置灰并带 tooltip 说明原因（不点了没反应）。

### 9.4 操作流程

```
首次  添加设备(≥1) → 选模式 → 确认声道数 → [自动绑定] → 逐路试听/对齐 → 开始分流
日常  打开(记住上次清单与模式) → 开始分流                 ← 两步
临时  运行中 → 加/删某张卡片 或 取消某条绑定 → 立即生效, 不断音
排错  状态行看模式/声道/水位 → 点警告徽标看具体哪条 → 点卡片定位到该声道
```

**踩到的坑（值得记，都是"看着对、跑起来歪"的那种）**：

- `Control.BackColor = Color.Transparent` 直接抛 `ArgumentException`（没开 `SupportsTransparentBackColor`）→ 启动即崩
- 用构造时的 `Width` 算右侧控件位置 + `Anchor = Right`：构造时宽度还是默认值，算出来的"到右边缘距离"是错的，控件被摆到屏幕外。设备行、卡片带、「已分配」、「刷新设备」全部改成 `OnResize` 里显式摆位
- 构造期 `Height = ...` 就会触发 `OnResize`，此时字段还没赋值 → `LayoutChildren` 必须先判空（这个坑踩了两次）
- `FlowLayoutPanel` 设了 `Anchor = Right` 而初始 `Size` 与宿主宽度不一致时，宽度会被算成几千像素，行里的控件跟着飞出屏幕
- 手动删过中间声道后，用 `Channels.Count` 当新声道序号会与已有的 key 撞车 → 新声道改用"最小未占用序号"


未做（按计划留给后续阶段）：`Validate` 还没接到 UI（P3）、ini 新 schema 与迁移（P2）、多声道模板还没有设备可测（P4，需要 ≥3 台设备或 5.1 端点）。

拼装拓扑真正要补的验证（P1 前做）：用 **VB-CABLE 配成 5.1 并设为默认输出**，确认 `WasapiLoopbackCapture` 拿到的 `WaveFormat` 是 6ch/48k，且 `DataAvailable` 的字节数能整除 `6 × 4`。本机已装 `VB-Audio Virtual Cable`（另有 网易虚拟音频设备 / MIXLINE 可用），但端点在 2026-11-15 的探测中仍是 2ch，**要先在 Windows「声音 → CABLE Input → 配置扬声器」里改成 5.1 再复测**。不验证就不知道 5.1 源是否真能拿到，整个 P4 的上混分支也就无法定稿。

## 11. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 用户以为"选 7.1 就变 7.1" | 功能预期落空 | UI 在设备行直接显示"端点实际 6ch"，映射对话框顶部写清前提 |
| 多路共享 ratio 在 3+ 路时收敛变慢 | 水位恢复慢 | `SwitchAfterUpdates` 按成员数归一；组内 >4 路时建议拆组 |
| 蓝牙多设备同时连接带宽不足 | 断续、爆音 | 启动前检测：若 >2 路蓝牙，提示"建议只保留 1~2 路蓝牙，其余用有线" |
| 上混系数导致削波 | 破音 | 预设留余量 + 硬限幅 + 限幅计数日志 |
| 单路重建时 COM 竞态 | 偶尔 `E_NOINTERFACE` | 沿用现有约束：`MMDevice` 只在引擎线程创建/释放，UI 只传 ID |
| 内存随路数线性增长 | 8 路 6ch ≈ 9MB | 可接受；`BufferDuration` 从 1000ms 收到 600ms 可减半（需重算 drift 余量） |
| **同一逻辑声道并联到多台设备** | 同空间两只音箱放同一信号：幅度相加最多 +6dB，且 1ms 级时间差在 250Hz 起形成梳状零点 | 绑定级增益默认降到 60%；卡片状态点标黄并提示"并联"；文档建议同空间只用一只，或把延迟对齐到 <0.5ms |
| **删声道连带删绑定，不可撤销** | 手搭半天点错一下就没了 | 卡片 `×` 先在浮层显示"将删除 3 条绑定"；删后 30 秒内状态行给「撤销」 |
| 逻辑层与设备层脱节（设备被拔） | 卡片显示"已绑定"但实际没声 | 绑定解析失败 → 卡片角标"离线"，状态行 `1 声道无输出设备`；启动仍允许（其余路正常） |
| 声道数 > 8 时卡片带过挤 | 横向滚动体验差 | 卡片带支持"紧凑模式"（只显示状态点 + 名称，宽 72）；>12 声道时自动切紧凑 |
| 实时刷新过频 | 拖数字框时界面卡顿 | 改动合并 30ms + `BeginUpdate/EndUpdate`；`Compile` 只在松手/失焦时跑，拖拽中途只更新计数 |

## 12. 不做清单

- 不做独占模式（历史原因：USB 标称/实测采样率偏差 10%，参见 `b83fdfa` 前的实验）
- 不做每设备独立 loopback 捕获
- 不做 ASIO / 内核流
- 不做跨设备采样级同步（无共同时钟源，做不到）
- 不做 LFE 低通滤波（`LFE` 抽头默认 `(L+R)×0.35`，文档标注"非标准 LFE"）
- 不做自动延迟测量 / 房间校正（需麦克风阵列与扫频分析，成本远超本需求；改为 §7.1 的人工标定）
- 不做"同一逻辑声道在多台设备间做等功率声像平移"（那是环绕声像控制，不是分发）
- 不做环绕声编码（Dolby/DTS bitstream 直通）
