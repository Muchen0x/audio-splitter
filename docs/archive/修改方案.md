## 2. 必须保持的行为契约

改造期间以下不变式**不允许改变**，作为所有回归的判断依据：

1. **UI 为权威源**：点「开始分流」时以 UI 值覆盖设备端点值（`WriteUIValuesToDevice`）。
2. **停止/失败/退出还原端点**：端点音量与静音还原到绑定前快照；UI 滑条**不回滚**。
3. **捕获消音锁定优先**：`chkMuteCapture` 勾选时，外部（系统音量条/快捷键/驱动）取消静音会被静默恢复；此时主静音不跟随。
4. **音量 0 ⇒ 静音勾选**：滑条到 0 自动勾选静音，拖离 0 自动取消；对左/右/主三处一致。
5. **默认输出切走 ⇒ 解绑不停流**：切回期望设备 ⇒ 自动重绑，UI 值回写设备。
6. **ini 写入时机**：仅非 `loadingSettings` 期落盘；300ms 防抖；`.tmp` + `File.Replace` 原子替换。
7. **单实例语义**：二次启动发激活事件唤起主窗口后自身退出。
8. **采样层与端点层分工**：主音量与增益走采样层（`DriftCorrectingProvider.Master/Gain`），左右音量走端点。

### 4.3 注意事项

- **资源名必须与旧 exe 完全一致**（4 个名字已从旧程序集读出）。构建后必须执行校验：
  ```powershell
  [Reflection.Assembly]::ReflectionOnlyLoadFrom('bin\Release\net48\SplitterGUI.exe').GetManifestResourceNames()
  ```
  少一个名字 = `AssemblyResolve` 兜底失效 = 分发单个 exe 时起不来。
- `Private=true` 保持"exe 旁有 dll"的现有形态（行为零变化）；若要纯单文件分发，改 `Private=false`，此时完全依赖内嵌资源。
- **不引入 `app.manifest` 的 DPI 声明**。当前 UI 是绝对坐标 + 系统缩放拉伸，声明 `dpiAware=true` 会让控件错位。DPI 改造留给 Phase 6 单独评估。
- `Log`、`IniPath` 均以 `Application.ExecutablePath` 为基准，输出路径变更不影响（仍取 exe 同目录）。

## 5. Phase 2 — 设备层重构（4–5h）　P0，解决 RCW 根因

### 5.1 现状病灶

`MainForm` 同时持有两种角色：`devices` 列表（供下拉框展示、会被 `RefreshDevices` 整体 `Dispose`）和 `syncDev/syncVol/syncLeftVol/syncRightVol`（长期订阅端点通知）。二者指向同一批 COM 对象，靠注释约定"端点不要 Dispose"维系。任何一条路径漏调 `UnbindAllVolumeSync` 或提前 `Dispose`，就会出现：

```
[ERROR] [配置] 2/4 主音量同步失败: COM 对象与其基础 RCW 分开后就不能再使用。
```

### 5.2 重构目标结构

```
Devices/
├─ DeviceCatalog.cs          枚举 + 纯数据端点描述 + 按 ID 解析，不长期持有端点引用
├─ EndpointVolumeBinding.cs  一个端点的音量/静音读写与通知订阅，自带失效自愈
├─ ChannelBindingSet.cs      主/左/右三条绑定的统一编排（替代三份重复代码）
└─ SystemDefaultPolicy.cs    PolicyConfig 封装（双 CLSID 回退）
```

#### DeviceCatalog

```csharp
sealed class EndpointInfo            // 纯数据，无 COM 引用，可安全跨线程传递
{
    public string Id, FriendlyName;
    public bool IsVirtual;
    public bool IsActive;
}

sealed class DeviceCatalog : IDisposable
{
    public IReadOnlyList<EndpointInfo> Endpoints { get; }
    public event Action Changed;

    public void Refresh();                       // 重新枚举；只 Dispose 自己拥有的 MMDevice
    public MMDevice OpenDevice(string id);       // 按 ID 新建独立实例，调用方负责生命周期
    public EndpointInfo Find(string id);
    public int IndexOf(string id);
    public string NameOf(string id);             // 已拔除设备返回 id 而不抛异常
}
```

**关键设计**：`DeviceCatalog` 内部持有的 `MMDevice` 只用于枚举与展示，**绝不参与端点音量操作**。所有端点操作通过 `OpenDevice(id)` 拿到独立实例，互相不干扰——这一条直接消灭 RCW 悬空。

#### EndpointVolumeBinding

```csharp
sealed class EndpointVolumeBinding : IDisposable
{
    public string DeviceId { get; }
    public bool IsValid { get; }
    public event Action Invalidated;             // 设备被拔/端点失效，UI 据此解绑并提示

    public float Volume { get; set; }            // 内部 try/catch，失败即 IsValid=false 并触发 Invalidated
    public bool Muted { get; set; }

    public void Subscribe();                     // 订阅 OnVolumeNotification，自身转发到 UI 线程
    public void Dispose();                       // 先退订 → 再 Dispose 自建 MMDevice（自建实例可安全 Dispose）
}
```

- 所有 COM 调用统一包 `Invoke(Action)`：捕获 `COMException`（`0x80070651` 设备已删除等），置 `IsValid=false`，触发一次 `Invalidated`，**不再向调用方抛**。
- 原代码里 `captureMuteEntered / captureMuteApplied / lastMuteWeWrote` 三个散落字段收敛为绑定内部状态：
  ```csharp
  public bool MuteEntered { get; private set; }   // 进入时原静音
  public bool MuteApplied { get; private set; }   // 是否由我们改动
  public void RestoreMuteIfApplied();
  public void ApplyMute(bool mute);               // 同步维护 MuteApplied 与 lastMuteWeWrote
  ```

#### ChannelBindingSet

三条通道（主/左/右）用同一套代码：

```csharp
sealed class ChannelBindingSet
{
    public EndpointVolumeBinding Master, Left, Right;
    public bool Bind(DeviceCatalog catalog, string masterId, string leftId, string rightId);
    public void UnbindAll();                                    // 还原音量 + 还原已改静音
    public void WriteUiValues(int master, int left, int right,
                              bool muteCap, bool muteL, bool muteR);   // 原 WriteUIValuesToDevice
    public void RestoreEnteredVolumes();                        // 原 UnbindAllVolumeSync 前段
}
```

| 现有成员 | 去向 | 处理 |
|---|---|---|
| `devices` `enumerator` `RefreshDevices()` `FindNameById` `FindIdxById` `DeviceIdAt` `IsVirtualDevice` | `DeviceCatalog` | 删除，改调新 API |
| `syncDev/syncVol` `syncLeftDev/syncLeftVol` `syncRightDev/syncRightVol` | `ChannelBindingSet` | 删除 |

## 6. Phase 3 — 启动健壮性（2h）　P0

### 6.1 启动前设备校验（解决 `尚未实现`）

`AudioEngine.Start` 取设备后立即校验：

```csharp
leftDev = enumerator.GetDevice(leftDevId);
if (leftDev.DeviceState != DeviceState.Active)
    throw new AudioDeviceUnavailableException("左声道设备不可用（可能已拔出），请刷新设备后重试");
```

捕获源同样校验，并核对**当前系统默认输出 ID 是否等于配置的捕获设备**；不等则抛"默认输出已被其他程序切走"。

### 6.2 预缓冲结果分级（解决 `L=0 R=0` 静默放行）

`Start` 返回 `StartResult`：

```csharp
enum StartOutcome { Ready, NoAudioYet, Insufficient }
```

| 条件 | 结果 | UI 行为 |
|---|---|---|
| `BufferedBytes >= target` 两侧 | `Ready` | `[启动] 分流已启动` |
| 等待超时且 `BufferedBytes > 0` | `Insufficient` | `[警告] 预缓冲不足(N 字节)，可能出现开头欠载` |
| 等待超时且 `BufferedBytes == 0` | `NoAudioYet` | `[警告] 捕获源 3 秒内无音频数据，已按静音启动`；首帧到达时补一行 `[启动] 音频流已就绪` |

### 6.3 异常翻译

新增 `AudioDeviceException` + 映射表，`StartFailed` 前把 HRESULT 转人话：

| HRESULT / 异常 | 提示 |
|---|---|
| `0x80070651` | 设备已被移除，请刷新设备 |
| `0x80070005` | 无权限访问音频设备（检查独占模式） |
| `0x88890008` | 设备不支持该采样格式 |
| `NotImplementedException` | 设备状态异常（多为已拔出仍在使用旧 ID） |
| 其它 | 原文 + `HRESULT=0x…` |

### 6.4 验收

- 拔掉左设备后点开始 → 弹窗为"左声道设备不可用（可能已拔出）"，而非"尚未实现"。
- 无声源场景点开始 → 日志出现"无音频数据，已按静音启动"，5 秒后出现"音频流已就绪"。

## 8. Phase 5 — 观测与兜底（1.5h）　P1

### 8.1 全局异常

`Program.Main` 在 `Application.Run` 之前：

```csharp
Application.SetUnhandledExceptionMode(UnhandledExceptionMode.CatchException);
Application.ThreadException += (s, e) => CrashReporter.Report(e.Exception, "UI");
AppDomain.CurrentDomain.UnhandledException += (s, e) => CrashReporter.Report(e.ExceptionObject as Exception, "AppDomain");
```

`CrashReporter`：写 `log/crash_yyyyMMdd_HHmmss.log`（异常全文 + 当前 AppState + 已绑定设备 ID），`MessageBox` 提示一次，随后退出并释放托盘。

### 8.2 日志规范化

- 级别枚举 `Info/Warn/Error`，`Log(string)` 保留兼容重载，内部按前缀推断。
- 文件行格式统一：`HH:mm:ss.fff [LEVEL] msg`（补毫秒，便于排查启动时序）。
- UI 层仍保留中文级别显示，避免观感变化。

### 8.3 验收

- 人为在 UI 线程抛异常（临时测试按钮）→ 生成 crash 日志、程序优雅退出、托盘图标消失。
- 日志文件可按 `grep "\[ERROR\]"` 精确检索。
