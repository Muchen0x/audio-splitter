# Stereo Splitter

把系统正在播放的声音**按声道拆开**，送到一台或多台输出设备上，每一路都能独立调节延迟、音量和静音。

典型用途：两个人各戴一副耳机（或一副耳机 + 一个音箱）听同一份声音，一边只听左声道、另一边只听右声道；也可以把 5.1 的六个声道分给三台立体声设备、或者把一路声音同时广播给所有设备。因为各路是**独立设备、独立时钟**，程序内部带有闭环漂移校正，长时间播放不会渐渐错位、也不会偏音。

> 面向 Windows 的桌面小工具，WinForms + NAudio，单文件 exe 即可运行。

---

## 工作原理

```
系统播放 ──► 捕获端点(通常是虚拟声卡) ──loopback──┐
                                                 │  原始多声道字节
                                    ┌────────────┼────────────┐
                                    ▼            ▼            ▼
                              设备A 延迟线   设备B 延迟线   设备C 延迟线
                                    │            │            │
                              按矩阵混音    按矩阵混音    按矩阵混音
                                    │            │            │
                              WasapiOut     WasapiOut     WasapiOut
                                    ▼            ▼            ▼
                                 设备A        设备B        设备C
```

1. 用 WASAPI loopback 从**捕获端点**抓取系统混音（格式跟随端点，48 kHz / 32 bit 浮点最常见）。
2. 同一份原始字节送进**每台设备**的延迟线（用于对齐设备之间的物理延迟差）。
3. 每台设备按自己的 `[输出声道 × 源声道]` 矩阵混音后写入一条 `WasapiOut`。矩阵由界面翻译而来：**一张输出卡片 = 一个声道 → 一台设备的一路**，落在同一台设备上的卡片按上下顺序占用该设备的物理声道 0/1/2…，因此一台设备只会被打开一次（同一端点开两条流会互相抢占、其中一路静音）。
4. 缓冲水位由闭环校正环盯住：水位偏低就微调重采样比率拉回，避免欠载爆音或缓冲堆积导致延迟越来越大。**立体声/单声道规格下所有设备共享同一个校正比例**（`ClockGroup`，消除偏音）；多声道规格下每台设备独立成组，否则个体水位发散会让设备间对齐随时间漂移。

## 系统要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（Windows 7 未验证） |
| 运行时 | .NET Framework 4.8 |
| 捕获端 | 建议用**一个虚拟声卡**（如 VB-Audio Virtual Cable、VoiceMeeter 等），需自行安装 |
| 输出端 | 任意一个或多个可独立发声的输出设备（板载 3.5mm、USB 声卡、蓝牙、HDMI 等），也可以一块多声道声卡直出 |

> 仓库**不包含**任何虚拟声卡驱动，请到对应厂商官网下载安装。安装后把系统默认播放设备设为该虚拟声卡，程序再从它的捕获端点取音；捕获端也可以直接选真实设备（此时系统声音会同时外放）。

## 构建

需要 .NET SDK（6.0 或更高，用于 `dotnet build` 编译 net48 目标）：

```bat
build.cmd
```

脚本会依次 restore → 编译 Release → 校验 NAudio 是否已内嵌 → 把成品同步到仓库根目录 `SplitterGUI.exe`。

`verify.cmd` 在构建之上额外检查源码是否有未提交改动、并统计 `log/` 体积。

NAudio（`NAudio.Core` / `NAudio.Wasapi` 2.2.1）以嵌入资源方式打进 exe，**发布时只需要一个 `SplitterGUI.exe`**，无需附带 dll。

## 使用

1. 安装并启用一个虚拟声卡，把系统默认播放设备切到它。
2. 启动 `SplitterGUI.exe`：
   - **捕获(虚拟)**：选择虚拟声卡的捕获端点。
   - **规格**：单声道 / 立体声 / 2.1 / 四声道 / 5.1，决定可选声道清单。源是真实多声道时按扬声器位直通，立体声源则按系数上混（中置 = 左右各 -6dB，低音 = 左右各 -9dB，环绕由前置派生）。
   - **输出卡片**：每张卡片 = 一路输出。选设备、选声道、填延迟(ms)、调音量、勾静音；「添加输出」可加到任意多路（上限 8 台设备 / 16 路），「×」移除。**同一台设备可以承载多路**，按卡片上下顺序占物理声道。
   - **延迟档位**：一套"预缓冲深度 + 输出缓冲"的预设组合，直接决定稳态延迟与抗断音能力。选项里标的是**总预估延迟**（捕获约 10ms + 内部缓冲目标 + 输出缓冲，不含 USB/DAC/声波）：标准 160ms → 低延迟 115ms → 极低 85ms → 超低 75ms → 极限 60ms。档位越低延迟越小，但缓冲余量越少，越容易出现断音/咔哒声。
   - **音量**：**独占一台设备的卡片**写该设备的**端点音量**（与系统音量条双向同步，停止时还原原值）；同一台设备上有多张卡时，这些卡走**混音增益**（端点音量是设备级单值，多路共用必然互相覆盖）。主音量与增益走采样层。
   - **还原**：开始分流时把每台输出设备"当时"的音量/静音记成基线（`[配置] … 音量绑定 → …（设备值 x%，停止时还原回此值）`）。停止、启动失败、退出分流、以及**运行中换设备/删卡**都会立即把写过的值还原回去，日志里逐台打印 `[还原] 左前 扬声器 …: 音量 12% → 20%（未静音）`。
     还原后会回读确认：设备没接受写入（USB 音箱/DAC 常见量化或只读）会记 `[警告] … 设备未接受该写入` 并保留基线，下次停止再试。基线在**成功还原前不会被覆盖**，避免出现"把 20% 还原成 20%"的空转。
   - **消音**：捕获端静音锁定——勾选后即使外部（系统音量条、快捷键、驱动）取消静音，也会被静默恢复。
   - **校正**：漂移闭环校正开关，默认开启。
   - **水位监控**：显示每一路的缓冲水位与校正比例，用于诊断卡顿/延迟增长。
3. 点「开始分流」。停止或退出时会还原各端点的音量与静音快照。

运行中可以即时改动：输出声道、静音、音量（进混音增益的那些卡片）会热替换混音矩阵，不停链路；**换设备或改延迟**属于链路级参数，需「停止 → 开始」才对生效（日志会提示）。换设备时旧设备的端点音量会当场还原。

窗口可关闭时最小化到托盘；二次启动会唤起已有窗口（单实例）。

### 自检

不需要声卡、也不会发声，只跑"卡片 → 声道抽头 → 混音矩阵"的断言（ini 往返也在内）：

```bat
SplitterGUI.exe --selftest
```

结果写到 `log/selftest-routing.txt`，退出码 0 = 全部通过。改动路由/上混系数后应当先跑它。

### 端点探针

只读，不改任何值，用来核对"音量到底还原了没有"（程序日志说还原了、Windows 音量合成器里却不是那个数时用它）：

```bat
SplitterGUI.exe --volprobe
```

打印每台输出设备的**端点真值**（音量/静音/是否默认）与 ini 里保存的 UI 值，同时写 `log/volume-probe.txt`。

## 目录结构

```
src/
  Audio/          抓取、延迟线、时钟组、路由模型（AudioEngine / SinkRuntime / Routing* / ClockGroup）
  Devices/        设备枚举、端点音量绑定、默认设备变更监听
  Infrastructure/ 日志、崩溃上报、ini 配置存取、错误文案、路由自检
  UI/             主窗体、输出卡片、把卡片翻译成路由模型（LaneRouting）
docs/             改造方案、修改计划、回归测试清单、多路内核移植说明
build.cmd         构建 + 内嵌资源校验 + 同步根目录 exe
verify.cmd        构建 + 工作区状态检查
```

运行日志写在 `log/session_*.log`，配置文件为 `SplitterGUI.ini`（均不入库）。

## 已知限制

- **不支持独占模式**：部分 USB 声卡标称 48 kHz 的实际采样率偏差可达 10%，超出 ±0.5% 的校正范围，强行独占会导致一侧被抽空直至静音，因此只使用共享模式。
- **蓝牙设备延迟较大且不稳定**，作为输出端时建议把延迟调大并使用较高的延迟档位（标准 / 低延迟）。
- **每台设备只有一条延迟线**：同一台设备上的多张卡片延迟不一致时，取最小值并在日志里提示。
- 依赖 Windows 扬声器位顺序表（KSAUDIO_SPEAKER_*）取源声道；非标准声道顺序的驱动无法识别。
- 「极限」档位在块粒度较大的捕获端点（如 HDMI）下会周期性见底，属于档位与设备周期不匹配，日志表现为欠载计数持续增长。
- 一路输出最多用到端点实际声道数 × 每声道一路，超出会被启动校验拦下（日志里的 `[路由]` 行说明原因）。
