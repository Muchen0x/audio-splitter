# Audio Splitter（多路音频分流）

把系统正在播放的声音**按声道拆开**，送到一台或多台输出设备上。每一路都能独立调节延迟、音量和静音，一台设备也只被打开一次。

**典型用途**：两个人各戴一副耳机听同一份声音（一人只听左声道、另一人只听右声道）；把 5.1 的六个声道分给三台立体声设备；或者把一路声音同时广播给所有设备。各路是**独立设备、独立时钟**，程序内置闭环漂移校正，长时间播放不会渐渐错位、也不会偏音。

> 面向 Windows 的桌面小工具，WinForms + NAudio，单文件 exe 即可运行。

---

## 功能特性

- **多设备分流**：最多 8 台设备 / 16 路，一张卡片 = 一台设备
- **任意声道矩阵**：单声道 / 立体声 / 2.1 / 四声道 / 5.1 规格下自由绑定；多声道设备可展开逐物理声道分配（p0/p1/…）
- **独立延迟**：每台设备 0~2000ms，用于对齐不同设备（蓝牙、USB、HDMI）的物理延迟差
- **音量双向同步**：卡片主音量直接写设备端点音量；停止时自动还原原值
- **时钟漂移校正**：闭环微调重采样比率，多设备长时间对齐不漂移
- **运行态自适应**：改声道热生效不停链路；不能热改的控件自动置灰
- **响应式界面**：卡片区按窗口宽度自动分栏，不出横向滚动条；日志区可拖到占满整窗
- **单文件分发**：NAudio 以嵌入资源打进 exe，拷走一个文件就能用

## 快速上手

1. **装一个虚拟声卡**（如 VB-Audio Virtual Cable、VoiceMeeter，需自行安装），把系统默认播放设备切到它。
2. 启动 `SplitterGUI.exe`：捕获端选虚拟声卡的捕获端点，选规格，给每台输出设备建一张卡片（选设备、选声道、调音量）。
3. 点**「开始分流」**。停止或退出时，各端点的音量/静音会自动还原。

> 也可以不装虚拟声卡直接捕获真实设备，此时系统声音会同时外放。

## 工作原理

```
系统播放 ──► 捕获端点(通常是虚拟声卡) ──loopback──┐
                                                 │  原始多声道字节
                                    ┌────────────┼────────────┐
                                    ▼            ▼            ▼
                              设备A 延迟线   设备B 延迟线   设备C 延迟线
                                    │            │            │
                              按矩阵混音    按矩阵混音    按矩阵混音
                                    │            │            │
                              WasapiOut     WasapiOut     WasapiOut
                                    ▼            ▼            ▼
                                 设备A        设备B        设备C
```

1. 用 WASAPI loopback 从**捕获端点**抓取系统混音（格式跟随端点，48 kHz / 32 bit 浮点最常见）。
2. 同一份原始字节送进**每台设备**的延迟线。
3. 每台设备按自己的 `[输出声道 × 源声道]` 矩阵混音后写入一条 `WasapiOut`。两张卡片选到同一台设备时会自动合并成一张多声道卡片——同一端点开两条流会互相抢占。
4. 闭环校正环盯住每路缓冲水位：水位偏低就微调重采样比率拉回，避免欠载爆音或延迟堆积。立体声/单声道规格下所有设备共享同一校正比例（消除偏音），多声道规格下每台设备独立成组。

## 使用指南

### 主界面

- **捕获(虚拟)**：选择虚拟声卡的捕获端点。捕获输出不能与左右目标相同，否则回环。
- **规格**：决定可选声道清单。源是真实多声道时按扬声器位直通；立体声源按系数上混（中置 = 左右各 −6dB，低音 = 左右各 −9dB，环绕由前置派生）。
- **输出卡片**：一张卡片 = 一台设备。选设备、选声道、填延迟、调音量、勾静音；「添加输出」加卡（上限 8 台 / 16 路），「×」移除。声道下拉里的**「多声道…」**可展开为逐物理声道分配，每行独立选声道、拖音量，选「（不使用）」= 该物理声道静音。
- **延迟档位**：一套预缓冲深度 + 输出缓冲的预设，标的是总预估延迟：标准 160ms → 低延迟 120ms → 极低 95ms → 超低 80ms → 极限 70ms。各档内部缓冲（时钟目标 55~100ms）已按大块粒度捕获端点的交货间隙校准，稳态剩余余量 ≥10ms。档位越低延迟越小，缓冲余量越少，越容易断音。
- **音量**：**主音量 = 设备端点音量**（与系统音量条双向同步，停止时还原）；多声道卡片里**行音量 = 该声道的混音增益**。形态切换时音量归属会自动搬家，保证响度不跳。
- **还原机制**：开始分流时记录每台设备当时的音量/静音基线；停止、退出、换设备、删卡都会立即还原，并回读确认写入是否被设备接受（USB 音箱/DAC 常见量化或只读，会警告并保留基线下次再试）。
- **消音**：捕获端静音锁定——勾选后即使系统音量条、快捷键取消静音，也会被静默恢复。
- **水位监控**：显示每路缓冲水位与校正比例，用于诊断卡顿/延迟增长，间隔 1~3600 秒（0 = 关闭）。

### 运行中哪些能改（界面按此规则置灰）

分流运行中只留**能真正生效**的控件可动，其余置灰（悬停有说明）：

| 层级 | 控件 | 运行中 | 原因 |
|---|---|---|---|
| 采样级 | 增益、主音量、各静音、卡片/行音量 | ✅ | 作用在采样层，立刻生效 |
| 矩阵级 | 卡片声道下拉、多声道行声道 | ✅ | 热替换混音矩阵，不停链路 |
| 监控级 | 校正开关、水位间隔、托盘选项、清除日志 | ✅ | 与链路无关 |
| 形态级 | 「多声道…」 | ⛔ 单项置灰 | 会改设备物理声道数，`WasapiOut` 已建好换不了，点了会还原并提示 |
| 链路级 | 捕获设备、规格、延迟档位、延迟数值、添加/移除卡片 | ⛔ | 要重建链路，须先停止 |

启动中全部暂时置灰（那一趟用的是按下按钮那一刻的配置快照）。

### 交互细节

- **滚轮只滚列表**：卡片区滚动时划过音量条、延迟框、下拉都不会误改值；音量只通过拖动滑条调节。
- **延迟步长 ±10ms**：上下按钮 / ↑↓ 每次跳 10ms，也可直接键入；**回车 = 提交并失焦**。
- **无焦点框**：点击按钮、复选框、下拉、数字框、音量条都不留虚线/蓝色焦点框。
- **自动分栏**：卡片区按基准宽度跳档换列（1~4 列），窗口变矮出竖向滚动条时卡片自动变窄，永远不出横向滚动条。
- **日志区**：分隔条无拖动上限，可拖到占满整窗；日志只在你本来就停在底部时自动滚底，往上翻历史不会被拽回。窗口整体变矮时内容区保底 284px，不会缩到只剩日志。
- **托盘**：关闭窗口可最小化到托盘，双击图标恢复；二次启动唤起已有窗口（单实例）。

## 命令行工具

```bat
SplitterGUI.exe --selftest        :: 路由自检 (16 项断言, 不发声, 退出码 0 = 全过)
SplitterGUI.exe --volprobe        :: 打印各端点真值 (音量/静音/默认) 与 ini 保存值, 只读
SplitterGUI.exe --list ["片段"]   :: 列出渲染端点 (可按名字过滤), 改之前先确认目标, 只读
SplitterGUI.exe --setvol "设备名片段:百分比"     :: 直接写端点音量 (可重复)
SplitterGUI.exe --setdefault "设备名片段"        :: 切换系统默认输出
```

`--setvol` / `--setdefault` 用于**强杀实例后的善后**：任务管理器结束进程或崩溃会跳过还原，端点音量停在分流值、默认输出挂在虚拟声卡上（整机无声）。先 `--list` 确认名字片段匹配到哪台设备，再用这两个开关修回。名字按子串匹配、不区分大小写；**片段匹配到多台设备时会拒绝执行并列出全部候选**（防止改错设备），换更长的片段重试即可。不加参数时程序是纯 GUI，没有任何隐式副作用。

## 构建

需要 .NET SDK 6.0+（编译 net48 目标）：

```bat
build.cmd     :: restore → Release 编译 → 校验 NAudio 内嵌 → 同步根目录 exe
verify.cmd    :: 构建 + 未提交改动检查 + log/ 体积统计
```

路由/上混系数改动后建议先跑 `--selftest`，结果写在 `log/selftest-routing.txt`。

## 已知限制

- **不支持独占模式**：部分 USB 声卡标称 48 kHz 的实际偏差可达 10%，超出 ±0.5% 校正范围，只使用共享模式。
- **蓝牙设备延迟大且不稳定**，作输出端建议用标准 / 低延迟档位并调大延迟。
- **每台设备只有一条延迟线**：同设备多张卡片延迟不一致时取最小值并在日志提示。
- 源声道识别依赖 Windows 扬声器位顺序表（KSAUDIO_SPEAKER_*），非标准声道顺序的驱动无法识别。
- 各档位的时钟目标已按大块粒度捕获端点（USB/HDMI 交货间隙实测消耗 ~35ms）校准，稳态剩余余量 ≥10ms，正常不应出现欠载持续增长；若仍见欠载，请反馈日志。
- 一路输出最多用到端点实际声道数，超出会被启动校验拦下（日志 `[路由]` 行说明原因）。
- **界面布局仅在 125% DPI（Windows 推荐）下验证过**：程序已声明 DPI 感知（无虚拟化模糊），但 100% 下窗口偏空旷、150% 下顶部规格行/卡片头部可能出现重叠，属于外观问题不影响功能。
